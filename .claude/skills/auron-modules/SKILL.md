# Auron — модульность и шина событий

Auron — платформа-конструктор, не набор жёстко связанных экранов. Новое добавляется, не
ломая старое. Эти основы закладываются с первого дня — переделать потом = переписать половину.

## 1. Модуль = отдельный файл, не правка существующего

Каждая функция — модуль (Касса, Поставщики, Персонал, Товары, ИИ). Включается/выключается
per-store в настройках. **Новый модуль = новый файл в `app/js/modules/` + регистрация в
`router.js`.** Существующий код не трогается.

```
app/js/modules/  home.js · kassa.js · journal.js · analytics.js · settings.js
```
Магазин без сотрудников работает без модуля Персонала — тот просто отключён.

## 2. Шина событий — модули общаются через события, не напрямую

Каждое действие публикует событие в центральную шину. Любой модуль подписывается и реагирует
независимо. Добавить реакцию = добавить слушателя, старый код не меняется.

```
shift.closed   → [Аудит] [Уведомление] [ИИ] [Вебхук] [Отчёт]
debt.added     → [Аудит] [Уведомление] [Календарь денег] [Кассовый разрыв]
payment.made   → [Аудит] [Уведомление] [Надёжность поставщика]
order.received → [Аудит] [Уведомление] [Склад] [Долг поставщика]
```

Не вызывай логику другого модуля напрямую — публикуй событие, пусть подпишется кто нужно.

## 3. Конфигурация вместо кода

Что показывать, какие поля обязательны, как считать — в конфигурации, не в коде:
справочники, обязательность полей, формулы расчётов, состав отчётов, набор и порядок
виджетов. Новый тип данных добавляется через конфиг, без деплоя. Не хардкодить это.

## 4. Кастомные поля везде

Каждая сущность (поставщик, сотрудник, заказ, товар) поддерживает произвольные поля.
Значения — в JSONB `custom_fields`, описание/валидация — в `custom_field_definitions`.
**Не расширять схему БД ради нового поля** — это миграция всех данных.

## 5. Движок прав, а не жёсткие роли

Роль = набор permissions. Новый модуль добавляет свои разрешения в тот же реестр — роли
расширяются автоматически. Подробно — skill `auron-rls-roles`.

## 6. Feature flags — включать фичи без деплоя

`feature_flags` (глобально) + `user_feature_flags` (переопределение per-user). Позволяет
включать функции отдельным пользователям/магазинам. Заложить с первого дня.

## 7. Трекинг каждого события

`analytics_events` копит каждое действие пользователя — данные для будущего ИИ накапливаются
пассивно с нуля. Не забывать публиковать события ключевых действий.

## Когда переходить на сборщик

v1 — монолит `index.html` без сборки (сознательно: ноль зависимостей). Переход на Vite —
когда `js/` превысит 15 файлов или суммарно 5 000 строк.

## Чек-лист новой функции

- [ ] Это новый файл-модуль + регистрация в `router.js`, а не правка чужого модуля
- [ ] Общение с другими частями — через события шины, не прямыми вызовами
- [ ] Настраиваемое живёт в конфиге, не захардкожено
- [ ] Доп. поля — через `custom_fields`, без миграции схемы
- [ ] Свои разрешения зарегистрированы в реестре permissions
- [ ] Ключевые действия публикуют события и пишутся в `analytics_events`
