# Тесты каталога — окружение и моки

Тесты — это Node-скрипты на Playwright, которые открывают приложение в браузере
с подменёнными данными. Ни сервера, ни интернета не требуется. Живут в
`catalog/tests/`, общая обвязка — `catalog/tests/helpers.js`.

## Окружение

- Модули Playwright — в системном пути: запускай с
  `NODE_PATH=/opt/node22/lib/node_modules node catalog/tests/run.js`.
- Приложение раздаётся статикой из папки `catalog`:
  `python3 -m http.server 8123 --directory catalog &` (порт 8123).
- Браузер Chromium уже установлен (`playwright install` не запускать).
- Контекст всегда мобильный: `viewport:{width:390,height:900}, isMobile:true,
  hasTouch:true, serviceWorkers:'block'`.

## Что подменяет helpers.js

`newPage(browser, { products, groups, popular, comp })` поднимает страницу и
перехватывает:

- `**/data/products.json`, `groups.json`, `popular.json`, `competitors.json` —
  отдаёт то, что передали в тест (по умолчанию пустые списки);
- `https://raw.githubusercontent.com/**` → 404 (зашифрованного снимка нет);
- `https://api.github.com/**` → `{}` (публикация никуда не уходит);
- в `localStorage` заранее кладётся фиктивный токен `wm_gh_token`.

`asOwner(page, {...})` — вход владельцем без сети: включает режим без сервера
и подкладывает закрытые данные (цены, продажи, поставщиков, конкурентов).

Помощники: `openProduct(page, id)`, `closeAll(page)`, `text(page, sel)`,
`runner(title)` → `{ chk, done }`.

## Грабли, на которые уже наступали

- **Порядок важен.** `js/config.js` подменяется первым; если сделать наоборот,
  настоящие настройки перезапишут подставленные, и тест незаметно пойдёт на
  живой магазин.
- **Смена адреса на тот же самый — не переход.** `openProduct` сначала
  очищает `location.hash`, иначе карточка не перерисуется и тест будет читать
  старое содержимое.
- **Проверять данные, а не картинку.** Приложение отдаёт наружу
  `window.WM_PUBLISH` (только на localhost): `_state()`, `_cat()`,
  `_renderStock()`, `_orderPlan()`, `_calcOffer()`, `_importOrder()`,
  `buildPublicProducts()`. Утечка в открытую витрину ловится по выходу
  `buildPublicProducts()` — по экрану её не видно.
- **Не зашивай в тест ожидаемый порядок/логику как константу.** Проверка
  порядка загрузок один раз оказалась пустой: она сравнивала свой же список
  сам с собой. Читай значение из приложения (`_importOrder()`).
- **Кириллица и `\b`.** В JS `\b` считает русские буквы не-буквами: `сок\b`
  никогда не совпадёт с «Сок Добрый». Пиши `сок(?![а-яё])`.

## Соглашение об успехе

Каждый тест печатает `OK:`/`FAIL:` по проверкам и в конце `=== … ОК ===` при
полном успехе, `process.exit(1)` при падении. `run.js` гоняет весь набор.

**Тест, который никогда не падал, ничего не доказывает.** Каждую новую
проверку прогоняй на старом коде (`git stash`) и убеждайся, что она валится.
