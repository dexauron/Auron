# Auron — PWA, кэш и деплой

## Правило №1: бампать версию кэша при каждом изменении фронта

`app/sw.js` использует имя кэша `auron-vNN`. **Каждое изменение фронта → увеличить NN**
(`auron-v12` → `auron-v13`). Иначе у пользователя останется старая закэшированная версия и
он не увидит правок. Это самая частая причина «я всё поменял, а на сайте старое».

## Правило №2: два приложения, две ветки, один деплой

Сайт https://dexauron.github.io/Auron/ собирается из **ДВУХ источников**:

| Приложение | Папка | Ветка |
|-----------|-------|-------|
| Auron (финансы) | `app/` | `claude/optimistic-einstein-Afzmv` |
| Каталог товаров | `catalog/` | `claude/store-product-catalog-60wer4` |

- `.github/workflows/deploy.yml` **одинаков в обеих ветках** и всегда берёт `app/` из ветки
  Auron + `catalog/` из ветки каталога.
- Пуш в одну ветку **не затрагивает** второе приложение.
- **Меняешь workflow — синхронизируй его в ОБЕ ветки**, иначе деплой рассинхронизируется.
- У каталога своя база (отдельный проект Supabase Cloud, ключи в `catalog/js/config.js`).
  С кодом и базой Auron НЕ смешивать.

> Примечание: текущая задача со скилами велась в отдельной ветке
> `claude/github-repo-rankings-ektgst` — это не деплойная ветка приложения. Изменения
> самого приложения идут в ветки из таблицы выше.

## Правило №3: офлайн = только просмотр

Service Worker кэширует последние данные (stale-while-revalidate). Ввод офлайн заблокирован.
Подробно — skill `auron-offline-sync`.

## Правило №4: v1 без сборщика

`app/index.html` (SPA) деплоится напрямую на GitHub Pages без сборки — сознательное решение
(ноль зависимостей, простой деплой). Переход на Vite — только когда `js/` превысит 15 файлов
или суммарно 5 000 строк.

## Чек-лист перед пушем фронта

- [ ] Увеличена версия кэша `auron-vNN` в `app/sw.js`
- [ ] Изменения в правильной ветке (Auron → ветка Auron, каталог → ветка каталога)
- [ ] Если правил `deploy.yml` — синхронизировал в обе ветки
- [ ] Не смешал `app/` и `catalog/` (разные базы, разные ключи)
- [ ] Проверил, что деплой собирает оба приложения корректно
