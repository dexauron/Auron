# Auron — финансовое ядро (двойная запись)

Три принципа профессиональной финансовой БД. Нарушение любого = потеря доверия к цифрам.

## 1. Двойная запись (double-entry)

Каждая операция создаёт **две строки**: дебет одного счёта и кредит другого. Сумма
дебетов = сумме кредитов в одной проводке. Баланс математически не может «потеряться».

- `journal_entries` — проводка (шапка): дата, описание, ссылка на бизнес-документ.
- `journal_lines` — строки: `account_id`, `debit_kopecks`, `credit_kopecks`, `memo`.
- **Правило:** Σ `debit_kopecks` = Σ `credit_kopecks` в рамках одной `entry_id`. Всегда.

`transactions` — это бизнес-уровень (что видит пользователь). Каждая транзакция ссылается
на свою проводку через `journal_entry_id`.

## 2. Неизменяемый реестр

`journal_entries` и `journal_lines` **не редактируются и не удаляются никогда.**

Ошибка исправляется **обратной проводкой (сторно):** `is_reversal = true`,
`reversal_of → исходная проводка`. В истории видна и ошибка, и исправление. Юридически чисто.

Два уровня данных — два правила удаления:
- **Реестр** (`journal_entries`, `journal_lines`) — неизменяем. Только сторно.
- **Бизнес-объекты** (`transactions`, `debt_entries`) — мягкое удаление через `deleted_at`:
  запись скрывается, попадает в корзину на 30 дней, а в реестре создаётся сторно.
- **Документы со статусом** (`shifts`, `purchase_orders`) — отменяются через `status=cancelled`,
  не удаляются.

Никогда не делай `DELETE` или `UPDATE` по финансовой сумме в реестре. Только новая
сторно-проводка.

## 3. Закрытые фискальные периоды

`fiscal_periods`: `status(open|closed|locked)`. После `locked` ни одна запись периода не
меняется — **даже администратором**. Налоговая приходит через 3 года — данные те же.

Исправление закрытого периода — только через `correction_requests`: бухгалтер пишет
причину → владелец одобряет → система создаёт сторно + новую проводку. Тихие правки задним
числом невозможны.

## Отмена Z-отчёта (частый кейс)

`shifts.status → cancelled`, и система автоматически:
1. создаёт сторно для всех связанных `journal_entries`,
2. снимает `is_locked` с транзакций смены,
3. помечает связанные `shift_withdrawals` отменёнными.

Всё видно в `audit_log`.

## Суммы — всегда в копейках

- Все деньги — **bigint в копейках** (`*_kopecks`). Никаких float, никаких рублей в БД.
- Деление на 100 — **только при отображении**. См. skill `auron-money-format`.

## Чек-лист

- [ ] Каждая операция → проводка с Σдебет = Σкредит
- [ ] Ничего не удаляется и не редактируется в реестре — только сторно
- [ ] Бизнес-объект удаляется мягко (`deleted_at`, корзина 30 дней) + сторно в реестре
- [ ] Закрытый период не трогается напрямую — только через `correction_requests`
- [ ] Суммы в копейках (bigint), деление на 100 лишь на экране
- [ ] Изменение отражено в `audit_log` (ДО/ПОСЛЕ)
