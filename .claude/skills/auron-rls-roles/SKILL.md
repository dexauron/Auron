# Auron — движок прав и изоляция

## Роль = набор разрешений, а не экран

Ключевое решение: роль — это **именованный набор permissions**, не фиксированный экран.

```
Разрешения (permissions): view_cash | edit_cash | view_debts | edit_debts |
                          view_staff | edit_staff | view_reports | manage_access | ...

Роль «Бухгалтер»     = [view_cash, edit_cash, view_debts, edit_debts, view_staff, ...]
Роль «Администратор» = [view_debts, create_order, view_products, ...]
Роль «Владелец»      = [view_*]  ← только чтение
```

Владелец может создать свою роль («Старший администратор») из любого набора разрешений.
Новый модуль добавляет свои permissions в ту же систему — роли расширяются автоматически.

**Проверяй доступ по конкретному permission (`shift.close`), а не по имени роли.** Имя роли
может быть любым пользовательским.

## Таблицы доступа

```
users          → профиль на человека (глобальная, без org_id)
organizations  → один магазин = одна организация
org_members    → user ↔ org ↔ role (многие-ко-многим; человек может быть в нескольких магазинах)
roles          → роли (таблица, не enum) · is_system
permissions    → реестр всех разрешений: key(unique) · module
role_permissions → role ↔ permission (составной PK)
```

Системные роли (`is_system`): `owner` (Владелец), `accountant` (Бухгалтер),
`admin` (Администратор), `staff` (Сотрудник зала). **Роли «Кассир» нет** — Auron не кассовая
программа.

## Изоляция: RLS по org_id

Каждая таблица данных содержит `org_id`. PostgreSQL Row-Level Security фильтрует по членству
пользователя в организации. Пользователь **физически не может** прочитать чужой магазин —
даже прямым запросом к PostgREST.

- Источник истины изоляции — RLS в БД, не клиентский фильтр.
- Storage-бакеты тоже под RLS: файлы организации видят только её участники.

## Временный и срочный доступ

- `substitute_assignments` — замещение: бухгалтер заболел → замена получает **только нужные
  permissions** на срок, истекают автоматически. В аудите видно: это замещение, не роль.
- `emergency_access_grants` — срочный доступ (потерян телефон), с `valid_until` и
  `device_fingerprint`.

## Безопасность входа

PIN 4 цифры (`pin_hash`), автоблокировка 1 мин (настраивается), 5 попыток
(`pin_attempts`) → блок (`pin_locked_until`) + сброс через email. Биометрия опционально.

## Чек-лист

- [ ] Доступ проверяется по permission-key, а не по имени роли
- [ ] На новой таблице есть `org_id` и RLS-политика изоляции
- [ ] Новый модуль регистрирует свои permissions в реестре
- [ ] Временный доступ выдаётся через substitute/emergency, а не сменой роли
- [ ] Действие с доступом отражено в `audit_log`
