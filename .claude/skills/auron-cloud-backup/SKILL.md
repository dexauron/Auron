# Auron — резервные копии в облако владельца

Принцип «ваши данные у вас»: копия всегда лежит там, где выбрал владелец. Главный аргумент
для недоверчивых к облакам.

## Три уровня (по дорожной карте)

| Уровень | Что | Куда | Когда |
|--------|-----|------|-------|
| 1. Автобэкап | Зашифрованный архив всех данных (JSON + CSV), ежедневно | Яндекс.Диск · VK Облако · СберДиск · Google Drive · Dropbox · любой WebDAV | v1 |
| 2. Файлы | Фото чеков/накладных в облаке пользователя | те же | v1.5 |
| 3. Своя база | Вся база на сервере клиента (self-hosted Supabase) | российские облака с PostgreSQL | v2+, тариф Сеть/Enterprise |

Живая база (одновременная работа кассира и бухгалтера, реальное время) **не может** работать
на файловом облаке типа Яндекс.Диска — это хранилище файлов, не БД. Поэтому уровни 1–2 —
это копии/файлы, а не рабочая база.

## Уровень 1 (v1) — как реализуется

- **WebDAV** — универсальный протокол: Яндекс.Диск поддерживает нативно, подходит и для NAS
  «в подсобке».
- **OAuth** — для Яндекс.Диска и VK Облака официальные API, подключение в два тапа.
- **Шифрование ДО отправки:** архив шифруется **паролем пользователя на клиенте** — облако
  видит только зашифрованный файл. Ключ/пароль в облако не уходит.
- **Восстановление:** загрузил архив → ввёл пароль → данные вернулись.

## Таблица

```
cloud_backup_connections:
  id · org_id · provider(yandex_disk|vk_cloud|sber_disk|gdrive|dropbox|webdav)
   · credentials_enc  ← доступ к облаку в зашифрованном виде
   · folder_path · schedule(daily|weekly|manual)
   · last_backup_at · last_status(ok|failed) · is_active
   · created_at · created_by
```

## Безопасность (см. skill `auron-security-antipatterns`)

- Пароль шифрования архива — **у пользователя**, на сервере не хранится. Потерял пароль →
  архив не восстановить (это осознанный размер: приватность важнее удобства).
- Доступ к облаку (`credentials_enc`) — только в зашифрованном виде, не в коде/логах.

## 152-ФЗ

Хранение копий в российских облаках помогает с локализацией данных — аргумент для
бизнес-клиентов. Российские провайдеры — первым выбором в UI.

## Чек-лист

- [ ] Архив шифруется паролем пользователя ДО загрузки в облако
- [ ] Пароль шифрования на сервере не хранится
- [ ] Доступ к облаку — в `credentials_enc`, не в открытом виде
- [ ] Расписание (daily/weekly/manual) и статус последней копии отражены
- [ ] Восстановление проверено: архив + пароль → данные назад
- [ ] Российские провайдеры предложены первыми (152-ФЗ)
