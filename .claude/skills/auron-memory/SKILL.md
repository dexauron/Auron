# Auron — протокол памяти

Память проекта живёт в файлах, не в моей оперативке. Это защита от забывания при сжатии
контекста, больших объёмах и между сессиями. Работать с ней — по этому протоколу.

## Где память

```
CLAUDE.md        — постоянные правила (читаются всегда)
docs/            — утверждённые решения по продукту + docs/DECISIONS.md
memory/
  README.md      — как устроено
  STATE.md       — снимок текущего состояния (читать первым)
  LOG.md         — журнал сессий (новое сверху)
  LESSONS.md     — ошибки и уроки
  GLOSSARY.md    — термины владельца
  PREFERENCES.md — как владелец хочет работать
```

## Начало сессии
1. Прочитать `memory/STATE.md` — где проект и что дальше.
2. При работе с незнакомой темой — заглянуть в `LESSONS.md`, `GLOSSARY.md`, `PREFERENCES.md`.
3. Не перечитывать всё подряд — брать нужное (принцип `auron-token-economy`).

## Во время работы
- Принято решение по продукту → строка в `docs/DECISIONS.md` + обновить нужный документ.
- Ошибка/грабли/полезная находка → в `memory/LESSONS.md` (коротко: что было → урок).
- Новый термин/сокращение владельца → в `memory/GLOSSARY.md`.
- Новое предпочтение владельца → в `memory/PREFERENCES.md`.

## Конец сессии
1. Обновить `memory/STATE.md`: этап, что сделано, что дальше, дата.
2. Добавить строку в `memory/LOG.md` (новое сверху).
3. Если что-то важное могло бы забыться — записать сейчас, не «потом».

## Правила ведения
- **Кратко и по делу.** Память — чтобы быстро сориентироваться. Раздутый файл = потеря
  времени и токенов. Устаревшее — обновлять, не копить.
- **Человекочитаемо.** Владелец — не программист, но может открыть и понять. Без жаргона.
- **Факты, а не пересказ.** Что решили и почему, чему научились — без длинных историй.
- **Одна правда.** Не дублировать `docs/`; память ссылается на них, а не копирует.
