# Auron Finance

Учёт денег для небольшого розничного магазина: кассовые смены, долги
поставщикам, товары, аналитика. Пишется владельцем магазина (не
программистом) вместе с ИИ.

> **Программисту, который открыл это впервые:** читайте следующие три
> раздела — они отвечают на «что работает», «где смотреть» и «во что не
> лезть». На это уйдёт минута, и она сэкономит вам час.

---

## Что работает прямо сейчас

Две живые версии, обе рабочие:

| Версия | Где живёт | Состояние |
|---|---|---|
| **Веб** (основная) | Google Apps Script + Google Таблицы | **в эксплуатации** в реальном магазине |
| **Android** | тот же код в оболочке Capacitor | собирается, подписана, работает без интернета |

Всё остальное в репозитории — заготовки и черновики, см. раздел
«Во что не лезть».

## Где что смотреть

### Хотите увидеть интерфейс

```
webapp/Index.html          ← весь экран: вёрстка, стили, логика (14 000 строк)
```

Открыть в браузере просто так нельзя — файл живёт внутри Apps Script и
ждёт сервер. Есть подмена:

```bash
node .claude/skills/look/scripts/gas.js webapp/Index.html /tmp/preview.html \
     webapp/tests/fixtures/ui-stub.json
# затем открыть /tmp/preview.html в браузере
```

Снимки экрана на телефоне и компьютере:

```bash
node .claude/skills/look/scripts/shot.js /tmp/preview.html
```

### Хотите увидеть логику

```
webapp/Code.gs             ← сервер: 329 функций, 9 300 строк
webapp/tests/*.test.js     ← 48 файлов проверок, запускаются в Node без фреймворков
```

Прогнать всё разом:

```bash
bash .claude/skills/preflight/scripts/preflight.sh
```

### Хотите понять архитектуру

```
docs/21-ARCHITECTURE-FOR-DEV.md   ← где сервер, где фронт, где бэк
```

Короткий ответ на частый вопрос: **рабочая версия живёт целиком в
Google**, а сервер на Timeweb — заготовка, приложение туда не переехало.

### Хотите понять замысел


## Во что не лезть

В репозитории лежат заготовки, которые **не используются**. Они не
удалены, потому что к ним, возможно, вернутся:

| Папка | Что это | Состояние |
|---|---|---|
| `app/` | версия на Supabase | заготовка, не запущена |
| `infra/`, `supabase/` | схема базы для той версии | написана, права по ролям проверены на живом Postgres |
| `server/` | пробный Node-сервер | черновик |

## Устройство репозитория — честно

Здесь беспорядок, и мы про него знаем:

- **главная ветка называется `claude/optimistic-einstein-Afzmv`**, а не
  `main` — так сложилось исторически;
- **одиннадцать веток**, в некоторых лежат разные проекты (каталог
  товаров — отдельное приложение со своим сервером);
- **восемь открытых запросов на слияние**, часть устарела.

Это следствие того, что проект ведёт не программист. Если возьмётесь
наводить порядок — начните с этого списка, он же самый полезный вклад.

## Чем помочь в первую очередь

Если спросите владельца «с чего начать», честный ответ такой:

1. **Разделить репозиторий.** Приложение, каталог товаров и заготовка на
   Supabase — три разных проекта в одном месте. Сборка сайта уже
   однажды стёрла каталог, потому что собирает его из трёх веток сразу.
2. **Домен и https.** Сервер отвечает по `http://201.51.6.170:8000` —
   пароли идут открытым текстом. Записано в `handoff/06-KNOWN-ISSUES.md`.
3. **Посмотреть на код свежим взглядом.** `Index.html` на 14 000 строк —
   это один файл, потому что Apps Script не даёт иначе. Но внутри он
   может быть аккуратнее.

## Ограничения площадки

Прежде чем предлагать сборщики, фреймворки и модули — учтите:

- фронт обязан быть **одним файлом** внутри Apps Script, сборщиков нет;
- серверная часть — **Apps Script**, не Node: нет npm, нет async/await
  в привычном виде, лимит 6 минут на вызов, кэш 100 КБ на ключ;
- база — **Google Таблицы** владельца, а не наш сервер. Это не
  недоработка, а решение: разработчик не должен видеть чужие деньги.

Подробнее — `docs/REVIEW-CONTEXT.md`.
