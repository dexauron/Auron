# Way Market — рекомендуемая архитектура

Статус: предложение ассистента 14.10.2026, **не утверждённое решение владельца**. Исходные ветки, опубликованные приложения, 1С и рабочие базы не изменяются. Основание: доступные исходники Auron Finance/каталога и предоставленные XLS/XLSX с фактическими колонками и ошибками старых формул.

## Целевой состав

| Часть | Для кого | Как работает сейчас без сервера | Граница данных |
| --- | --- | --- | --- |
| Публичный каталог PWA | Покупатель на телефоне | Отдельная статическая сборка, поиск, фото, цены, наличие с датой, список покупок, ссылка на WhatsApp для самовывоза или доставки. Нет оплаты и личного кабинета заказов. | Только специально экспортированные публичные поля. Популярность — только по проверенным агрегатам. Источник и дата обновления показаны; неизвестное наличие не выдают за точное. |
| Закрытая программа Windows | Владелец, бухгалтер, администратор и сотрудники по ролям | Локальная база SQLite на одном рабочем компьютере, импорт 1С, накладные, выплаты, долг, сверка, KPI, аудит, резервная копия и восстановление. | Полные внутренние данные остаются локально. UI не исполняет произвольный SQL или JavaScript формул. Роли проверяются в слое операций, не только скрытием кнопок. |
| Общие типы и методики | Разработчики обеих частей | Общее ядро TypeScript/JavaScript: определения разрешённых публичных полей, схемы импорта, денежная арифметика, версии KPI и сверки, синтетические тесты. | Общее ядро не означает общий файл базы или публичный доступ к финансовым таблицам. |

**Технологическое предложение:** адаптивный веб-интерфейс TypeScript для обеих сборок, закрытая Windows-оболочка Tauri 2 с командами на Rust, SQLite и локальным чтением `.xls`/`.xlsx` через библиотеку Calamine. Tauri допускает веб-интерфейс и Windows-установщик; Calamine читает XLS/XLSX и имеет лицензию MIT. Это предложение следует проверять на целевом Windows ПК и предоставленных файлах до фиксации стека. [Tauri](https://tauri.app/start/), [Windows](https://v2.tauri.app/distribute/windows-installer/), [Calamine](https://github.com/tafia/calamine).

**Новая цель владельца:** после настройки дизайна, бизнес-логики и архитектуры должна быть возможность перенести закрытую часть в веб-приложение без потери данных и переписывания правил расчёта. Это требование к проектированию с самого начала, не обещание, что Tauri-сборка запускается в браузере без изменений.

| Стабильная часть | Заменяемая граница при переходе в веб |
| --- | --- |
| Адаптивные экраны и состояние UI без прямых обращений к Tauri | Адаптер платформы для выбора файла, сохранения копии и системных диалогов |
| Чистые правила маржи, прибыли, лимитов и сверки с тестами | Локальный SQLite на одном ПК → серверный API и база для нескольких сотрудников; веб-клиент хранит только разрешённый офлайн-кэш |
| Канонические модели событий и идентификаторы, журнал изменений, версии схем | Импорт XLS/XLSX через локальный адаптер → безопасная серверная обработка или разрешённый браузерный парсер |
| Публичный экспорт каталога по белому списку | Ручная публикация → отдельный защищённый канал обновления каталога |

Зависимости на `window.__TAURI__`, путь к файлу SQLite и операции с файловой системой держать за типизированными интерфейсами. Не переносить данные финансов в публичный браузерный пакет. Перед веб-запуском нужны серверная авторизация, проверка прав при каждом запросе, транзакции, резервные копии, миграция локальных записей с повторяемым импортом и правила разрешения конфликтов. Перенос проверять на копии базы: сверить число документов, суммы, версии формул и баланс; только после сверки переключать пользователей. Статический хостинг не заменяет серверную часть этой системы.

Почему локальная база у сотрудников: можно начать без платного сервера и работать без интернета. Для денег и журнала операций нужны транзакции, уникальные ключи, история корректировок и ежедневная резервная копия. Браузерное хранилище удобно для списка покупок, но не следует делать его единственной копией внутренней финансовой базы: данные сайта зависят от политики хранения браузера. [MDN о хранении](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Публичный каталог может оставаться на статическом хостинге без бэкенда при ручном выпуске обновлённого набора товаров. GitHub Pages обслуживает статические HTML/CSS/JS и не выполняет серверный код. Не публиковать там отчёты 1С, контакты, закупочные цены или внутреннюю базу. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [ограничение серверного кода](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Принципы взаимодействия и границы операций

Запрос владельца: опираться на последовательность, понятную обратную связь и фокус на текущей задаче по принципам дизайна Apple. Подробный документ с картой экранов, состояний и проверок — `docs/WAY_MARKET_EXPERIENCE_PRINCIPLES.md`. Это проектное направление, а не заявление, что весь код уже соответствует ему.

UI не проводит движение денег непосредственно: пользователь запускает команду, прикладной слой проверяет роль, магазин, сумму в копейках, версию записи и ключ повторной отправки; затем одной транзакцией сохраняет бизнес-событие, движение счёта и аудит. Ответ содержит подтверждённый ID или конкретную причину, что нужно уточнить. Разные состояния «запрошено», «назначено», «выдано» и «принято бухгалтером» имеют разные источники и не подменяют друг друга.

Данные из бумажного табеля сначала перенесены человеком и сверены с оригиналом; неперенесённый день не считается отсутствием. Отчёт печатается из зафиксированной версии и не проводит выплату. Версии формулы кассы и уже утверждённые снимки сохраняются, чтобы изменение настройки не переписывало прошлое. Один словарь статусов и единый расчёт используют мобильная и компьютерная версии; текущие HTML-макеты — отдельные файлы и пока дублируют код.

## Поток данных

1. Сотрудник экспортирует файл из 1С. Локальное приложение читает его без макросов, определяет тип по шапке, показывает период и предпросмотр, проверяет контрольные итоги, пропуски, дубли и связи. Ошибочные строки остаются на проверке. Исходный файл и 1С не переписываются.
2. После подтверждения импортёр заменяет версию агрегированного снимка за тот же период либо добавляет новые уникальные документы одной транзакцией, сохраняет контрольную сумму, автора, версию парсера и историю изменения. Заказ, приход, долг, платёж, списание и возврат остаются разными событиями.
3. Расчёт KPI читает только проверенные источники совпадающего периода и учётной основы; неполный текущий месяц помечает «предварительно». Выплаты поставщику меняют денежный счёт, себестоимость проданного определяет валовую прибыль. Настраиваемая пользователем формула относится к сверке кассы и управленческим строкам, а не переопределяет определения прибыли.
4. Отдельная операция формирует разрешённый публичный экспорт каталога без внутренних полей. Обновление публикации — ручное до появления безопасного сервера синхронизации. Покупатель видит дату последнего обновления и может отправить сформированный список в WhatsApp.

## Порядок разработки

1. Реальные профили импорта XLS/XLSX и экран предпросмотра на тестовой локальной базе; начать с продаж, РКО и накладных. Уже существует чистый разбор *прочитанных ячеек* продаж в `way-market/importers/one-c-sales.mjs`, но бинарный читатель, UI и сохранение ещё отсутствуют.
2. Схема SQLite и журнал: источник, период, документы, позиции, связи, движение денег, роли, версия формул, аудит и восстановление после прерванного импорта. Встроить проверку прав и резервную копию.
3. Касса и сверка на тестовой смене с независимой фактически пересчитанной бухгалтером суммой; затем расходы и прибыль только после получения учётной политики. Показывать недостающие данные, а не ноль.
4. Сборка публичного каталога с разрешёнными полями, мобильная проверка iOS/Android и отдельная проверка Windows-установщика. Ни клиент WhatsApp, ни покупательский каталог не проводят финансовую операцию.
5. Позднее, когда нужны несколько рабочих компьютеров/магазинов и есть бюджет: отдельный сервер и API с синхронизацией, конфликтами, правами и резервными копиями. До этого локальная база на одном ПК **не даёт совместную работу в реальном времени** другим устройствам. Выбор размещения и правовая проверка данных — отдельное решение перед пилотом.

## Что проверить до закрепления выбора стека

- Windows и права установки на реальном ПК, включая WebView2; релизный установщик пока не готов. [Tauri prerequisite](https://v2.tauri.app/start/prerequisites/).
- Calamine на образцах 1С: числа с запятой, кодировки XLS, русские даты, огромные листы и неисполнение макросов. Не переносить сырой парсер в веб-каталог.
- Хранение и восстановление SQLite при выключении ПК во время импорта; уникальные ключи, миграции и резервные копии.
- Для покупателей — доступность без интернета после первой загрузки, дата публичного экспорта и отсутствие внутренней информации во всём пакете сборки.
