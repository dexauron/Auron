# Техническое задание: Auron Finance

Учёт денег небольшого розничного магазина.
Версия ТЗ 1.0 · 07.08.2026

---

## 1. Общие сведения

### 1.1. Назначение

Приложение для владельца небольшого продуктового магазина, ведущего
учёт самостоятельно, без бухгалтера. Заменяет тетрадь и таблицы Excel,
не требуя внедрения 1С.

### 1.2. Цели

| Цель | Проверяемый признак достижения |
|---|---|
| Владелец в любой момент знает сумму долга поставщикам | цифра на главном экране, обновляется при каждой записи |
| Владелец видит расхождения по кассе | расхождение считается автоматически при закрытии смены |
| Учёт занимает не более 5 минут в день | запись смены — не более 12 полей ввода |
| Данные не теряются | автоматическая копия раз в сутки + копия файлом |

### 1.3. Термины

- **Смена** — рабочий день кассира: выручка, инкассация, выплаты.
- **Слепая инкассация** — кассир вводит фактическую сумму в лотке, не
  видя ожидаемую. Расхождение видит только владелец.
- **Замок периода** — дата, ранее которой записи нельзя менять.
- **Контрагент** — поставщик или получатель платежа.

## 2. Пользователи

### 2.1. Роли и права

| Роль | finance | kassa | receive | goods | payments | manage |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| Владелец | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Администратор | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| Бухгалтер | ✓ | — | — | ✓ | ✓ | — |
| Сотрудник зала | — | ✓ | ✓ | — | — | — |

Расшифровка: **finance** — доходы, расходы, прибыль, аналитика;
**kassa** — запись смен; **receive** — приём товара и накладные;
**goods** — товары и цены; **payments** — выплаты и долги;
**manage** — настройки, сотрудники, права, замок периода.

### 2.2. Требование к проверке прав

**Т-2.1.** Права обязаны проверяться на стороне сервера (или базы
данных) при каждом обращении. Скрытие элементов интерфейса защитой не
считается.

*Приёмка:* обращение к данным в обход интерфейса под учётной записью
сотрудника зала не возвращает финансовых данных и зарплат.

## 3. Функциональные требования

### 3.1. Кассовая смена

**Т-3.1.1.** Запись смены содержит: дату, название смены, кассира,
выручку наличными, выручку по каналам безналичной оплаты, сумму
оплаченного поставщикам наличными, сумму, оставленную в кассе, сумму
инкассации.

**Т-3.1.2.** Расхождение считается по формуле:
`(инкассация + оплачено поставщикам + оставлено) − выручка наличными`.

**Т-3.1.3.** При слепой инкассации кассиру не отображается ожидаемая
сумма ни до, ни после ввода.

**Т-3.1.4.** После успешного сохранения форма очищается полностью,
кроме даты, названия смены и кассира.

*Обоснование: незачищенная форма приводила к повторной записи той же
смены по тем же цифрам.*

**Т-3.1.5.** По итогам смены формируется чек с составом сумм и
расхождением, пригодный для отправки сообщением.

*Приёмка:* содержимое чека на экране и в отправляемом тексте совпадает
по всем числам.

### 3.2. Накладные и долги поставщикам

**Т-3.2.1.** Вечерняя часть смены заполняется **по каждому поставщику
отдельной строкой**: оплачено, погашено долга, взято в долг.

**Т-3.2.2.** Поддерживаются два режима: подробный (построчно) и общей
суммой. Режим переключается в настройках.

**Т-3.2.3.** Поиск поставщика при вводе — по части названия, независимо
от раскладки клавиатуры и языка ввода.

**Т-3.2.4.** Общий долг равен сумме долгов всех поставщиков, включая
отрицательные (переплаты).

*Обоснование: при отбрасывании переплат выплата поставщику, за которым
долга не числилось, не уменьшала общую сумму.*

**Т-3.2.5.** Строка без указанного поставщика с ненулевой суммой не
сохраняется, выдаётся понятная ошибка.

### 3.3. Операции

**Т-3.3.1.** Операция содержит: дату, тип (доход/расход/перевод),
категорию, сумму, счёт, комментарий, автора.

**Т-3.3.2.** Правка операции изменяет существующую запись, а не создаёт
новую.

**Т-3.3.3.** Переводы между своими счетами не учитываются в доходах и
расходах.

**Т-3.3.4.** Суммы хранятся в целых копейках.

*Обоснование: на закупочной цене 0,09 ₽ и наценке 30% дробные числа
дают расхождение в рублях на объёме 16 500 позиций.*

### 3.4. Замок периода

**Т-3.4.1.** Владелец задаёт дату, ранее которой записи неизменяемы.

**Т-3.4.2.** Замок блокирует: изменение существующей записи, удаление,
создание новой записи датой ранее замка, **перенос даты записи в
закрытый период**.

*Обоснование: без последнего пункта замок обходится сменой даты.*

**Т-3.4.3.** Замок действует на всех, включая владельца.

### 3.5. Аналитика

**Т-3.5.1.** Показатели за период: выручка, расходы, прибыль, маржа.

**Т-3.5.2.** Разбивка по категориям с долями.

**Т-3.5.3.** Под каждым показателем — сравнение с предыдущим таким же
периодом словами: «как обычно», «выше обычного на N%», «ниже обычного
на N%».

**Т-3.5.4.** Порог значимости — 8%. Меньшее отклонение обозначается как
«как обычно».

*Обоснование: без порога подписи появляются на обычных колебаниях
торговли и перестают восприниматься.*

**Т-3.5.5.** Направление оценивается по смыслу: рост выручки —
положительно, рост расхода — отрицательно.

**Т-3.5.6.** Убыток сравнивается по модулю: −50 против −100 — улучшение.

**Т-3.5.7.** При отсутствии данных за предыдущий период сравнение не
выводится.

### 3.6. Товары

**Т-3.6.1.** Хранение справочника: штрихкод, наименование, группа,
единица, поставщик, цена закупки, цена розницы, остаток.

**Т-3.6.2.** Импорт выгрузки из 1С в формате Excel (.xls/.xlsx).

**Т-3.6.3.** Поиск по наименованию и штрихкоду, устойчивый к ведущим
нулям в штрихкоде.

**Т-3.6.4.** Отчёт «что заканчивается»: позиции, у которых остаток
меньше половины проданного за период.

**Т-3.6.5.** История цен закупки и розницы.

### 3.7. Выплаты и календарь

**Т-3.7.1.** Плановая выплата: контрагент, сумма, дата, назначение,
статус.

**Т-3.7.2.** Счётчик ожидающих выплат отображается на элементе
навигации.

**Т-3.7.3.** Просроченные и предстоящие выплаты выделяются разным
цветом.

### 3.8. Сотрудники

**Т-3.8.1.** Приглашение сотрудника по адресу электронной почты с
назначением роли.

**Т-3.8.2.** Приглашать вправе только владелец.

**Т-3.8.3.** Приглашённый по ссылке присоединяется к существующему
магазину, свой не создаёт.

**Т-3.8.4.** Табель: явка, часы, ставка, сумма к выплате.

### 3.9. Резервное копирование

**Т-3.9.1.** Автоматическая копия не реже раза в сутки без участия
пользователя.

**Т-3.9.2.** Хранение не менее 7 последних копий.

**Т-3.9.3.** Выгрузка копии файлом для переноса на другое устройство.

**Т-3.9.4.** Загрузка копии **замещает** данные целиком.

**Т-3.9.5.** Перед замещением пользователю показывается количество
записей в текущих данных и в копии, требуется подтверждение.

**Т-3.9.6.** Перед замещением создаётся страховочная копия текущего
состояния.

**Т-3.9.7.** Даты в копии сохраняют тип при выгрузке и загрузке.

*Обоснование: при сериализации в текст даты становятся строками, копия
загружается без ошибок, но данные не читаются.*

**Т-3.9.8.** После загрузки копии кэш сбрасывается.

### 3.10. Уведомления

**Т-3.10.1.** Напоминание о закрытии смены в заданное время (по
умолчанию 21:00), с возможностью изменить час и отключить.

**Т-3.10.2.** Напоминание о выплате в день платежа.

**Т-3.10.3.** Несколько выплат одного дня объединяются в одно
уведомление.

**Т-3.10.4.** Повторное уведомление об одном событии в течение суток не
отправляется.

**Т-3.10.5.** Ранее запланированные уведомления снимаются перед
постановкой новых.

*Обоснование: без этого при каждом запуске накапливаются дубликаты.*

## 4. Нефункциональные требования

### 4.1. Производительность

Расчётные объёмы: 16 500 товаров, 22 000 строк истории цен, 578
контрагентов, 120 операций в день, выгрузка из 1С до 7 МБ (23 500
строк).

| Операция | Предельное время |
|---|---|
| Открытие главного экрана | 2 с |
| Пересчёт аналитики за месяц | 3 с |
| Поиск товара | 0,5 с |
| Импорт выгрузки из 1С | 60 с |

### 4.2. Надёжность

**Т-4.2.1.** Обрыв связи при сохранении не приводит к потере введённых
данных.

**Т-4.2.2.** Повторная отправка одной операции не создаёт дубликат.

**Т-4.2.3.** Запись смены, приёма товара и накладных возможна без
интернета с последующей отправкой.

### 4.3. Безопасность

**Т-4.3.1.** Права проверяются на сервере (см. Т-2.1).

**Т-4.3.2.** Передача данных по защищённому соединению (https).

**Т-4.3.3.** Данные разных магазинов изолированы.

**Т-4.3.4.** Действия с деньгами фиксируются в журнале с указанием
автора и времени.

### 4.4. Соответствие законодательству РФ

**Т-4.4.1.** Персональные данные граждан РФ хранятся на серверах,
расположенных в РФ (152-ФЗ, ст. 18 п. 5).

**Т-4.4.2.** Опубликована политика обработки персональных данных,
согласие запрашивается явно.

**Т-4.4.3.** Уведомление в Роскомнадзор подаётся до начала обработки.

**Т-4.4.4.** Объём хранимых персональных данных минимизируется.

## 5. Интерфейс

### 5.1. Цветовая схема

```
фон                #07090C      карточка         #101318
вложенная карточка #161A21      текст            #F3F4F6
второстепенный     #8E8E93      линии            rgba(255,255,255,.075)

акцент «нажать»    #C5F82A
пришло / хорошо    #30D158
ушло / опасность   #FF453A
```

**Т-5.1.1.** Количество смысловых цветов — не более трёх. Введение
дополнительных цветов для оформления диаграмм не допускается.

### 5.2. Типографика и ритм

**Т-5.2.1.** Отдельная гарнитура для числовых значений, моноширинная
по цифрам.

**Т-5.2.2.** Задан запасной системный шрифт; при недоступности внешних
шрифтов вёрстка сохраняется.

**Т-5.2.3.** Отступы кратны 4 px. Скругления: 20 px основные, 14 px
мелкие, 24–28 px акцентные.

### 5.3. Правила подачи информации

**Т-5.3.1.** Числовой показатель сопровождается пояснением (сравнением
или единицей измерения).

**Т-5.3.2.** Пустое состояние экрана содержит объяснение и действие.

**Т-5.3.3.** Необратимое действие сопровождается указанием последствий
и подтверждением.

**Т-5.3.4.** Интерфейс на компьютере и телефоне отличается плотностью
и раскладкой, но не набором функций.

### 5.4. Отклик

**Т-5.4.1.** Нажатие сопровождается визуальным откликом за время не
более 100 мс.

**Т-5.4.2.** Операция длительностью более 300 мс сопровождается
индикатором.

## 6. Приёмка

### 6.1. Обязательные проверки

| № | Что проверяется | Ожидаемый результат |
|---|---|---|
| П-1 | Запись смены с расхождением | расхождение посчитано, форма очищена |
| П-2 | Кассир открывает аналитику | доступ не предоставлен |
| П-3 | Обращение к данным в обход интерфейса под учётной записью кассира | финансовые данные не возвращены |
| П-4 | Запись задним числом в закрытый период | отклонена |
| П-5 | Перенос существующей записи в закрытый период | отклонён |
| П-6 | Выплата поставщику с переплатой | общий долг уменьшился |
| П-7 | Выгрузка и загрузка копии | все суммы и даты совпадают |
| П-8 | Загрузка копии при наличии данных | показано число теряемых записей |
| П-9 | Обрыв связи при сохранении смены | данные сохранены, отправлены позже |
| П-10 | Повторная отправка одной операции | дубликат не создан |
| П-11 | Импорт выгрузки 23 500 строк | уложился в 60 с |
| П-12 | Показатель без данных за прошлый период | сравнение не выводится |

### 6.2. Автоматические проверки

**Т-6.2.1.** Расчётная логика покрыта автоматическими тестами.
Изменение, ломающее расчёт денег, обязано приводить к падению теста.

**Т-6.2.2.** Выкладка при непройденных тестах не производится.

## 7. Ограничения и допущения

**7.1.** Приложение не является кассовой программой по 54-ФЗ и не
заменяет онлайн-кассу.

**7.2.** Приложение не ведёт бухгалтерский и налоговый учёт и не
формирует отчётность для ФНС.

**7.3.** Целевая аудитория — магазины с одной торговой точкой и не
более чем пятью сотрудниками.

**7.4.** Учёт ведётся в рублях, мультивалютность не требуется.

---

## 8. Что осознанно не входит в объём

- интеграция с онлайн-кассой и ККТ;
- обмен с 1С в обе стороны (только импорт файлом);
- складской учёт с партиями и себестоимостью по FIFO;
- работа нескольких торговых точек в одной базе;
- мультивалютность.
