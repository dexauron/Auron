# Защита данных каталога — 27.10.2026

Каталог работает с GitHub-файлами. Старые SQL-миграции из описания PR #4
относятся к прежней Supabase-версии и для этого импорта не нужны.

## Доступ к данным

| Роль | Что получает | Что может менять |
|---|---|---|
| Покупатель | Публичные названия, коды, штрихкоды, фото, розничные цены, признак наличия | Свой местный список покупок |
| Сотрудник-бухгалтер (`staff`) | Разрешённые товарные реквизиты, закупки, продажи, поставщики, контакты, опубликованные заказы | Не публикует и не редактирует общий каталог |
| Владелец (`owner`) | Полный каталог и настройки доступа | Публикация через собственный GitHub-ключ |

Копирование публичной витрины допустимо по устройству приложения: эти данные
браузер получает без входа. Удаление кнопки скачивания не закрывает JSON.
Зашифрованные файлы также можно скачать, но для чтения нужен соответствующий
секрет. GitHub-токен даёт право записи; пароль каталога сам по себе такого
права не даёт. Не выдавать токен публикации сотрудникам.

## Формат v4

- Независимые случайные 256-битные ключи owner/staff. Пароль staff не открывает
  файлы owner. В выдачу staff не включаются пароль сотрудника, заявки владельца
  и неизвестные поля товара: применяется список разрешённых полей.
- `catalog.enc` + `sec/` — owner; `staff-catalog.enc` + `sec-staff/` — staff.
  `keys.json` содержит только парольные конверты ключей.
- AES-GCM связывает ключ, роль и назначение каждой части через additionalData.
  Перестановка описи/частей между ролями и типами данных отклоняется.
- Новые парольные конверты: PBKDF2-HMAC-SHA256, 600 000 итераций, случайные
  соль и IV. Чтение старых конвертов учитывает их iter; параметры ограничены.
  Параметр взят из OWASP Password Storage Cheat Sheet, проверенной 27.10.2026.
- Новые пароли от 12 символов; владелец и сотрудник используют разные пароли,
  в том числе при смене пароля staff после восстановления входа без исходного
  пароля owner в памяти. Рекомендуется длинная уникальная фраза.
  При вводе и шифровании строка пароля передаётся точно: крайние пробелы не обрезаются.
- Обычная правка переписывает только изменённые части каждого разрешённого
  набора. Смена пароля staff меняет его ключ. Явная смена owner перешифровывает
  оба набора. Все файлы и указатели публикуются одним Git-коммитом.

## Переход существующего магазина

Перед переходом закрыть старые вкладки владельца, открыть обновлённое приложение
и зафиксировать SHA текущего коммита данных. Сохранить старые пароли до сверки
результата. Предыдущая версия файлов остаётся в родительском коммите источника;
откат после v4 требует согласованной пары кода и данных, а не только старого JS.

1. Войти владельцем старым паролем. v3 и прежний цельный файл читаются для
   перехода. Вход staff с прежним общим ключом блокируется с объяснением.
2. Открыть меню → «Пароль каталога».
3. Ввести новый пароль владельца, повторить его и в этой же форме задать
   другой новый пароль сотрудника. Каждый от 12 символов. Это позволяет
   обновить оба слабых старых пароля без взаимной блокировки форм.
4. Дождаться успешной публикации. Перешифрование выполняется на устройстве;
   сообщать пароли исполнителю не нужно. При отказе записи прежние удалённые
   файлы не заменяются, а временная смена staff-пароля в форме отменяется.
5. Проверить вход обоими новыми паролями и отказ старых на актуальных файлах.
   Сверить количество товаров, групп, поставщиков, цены, штрихкоды и фото.

Обновление кода само по себе **не перешифровывает уже опубликованные данные**.
Без доступа владельца к расшифрованному каталогу исполнитель не может сделать
этот переход за него. Не заменять реальные файлы пустыми/демонстрационными и
не объявлять защиту рабочих данных завершённой до шага 4.

Если опись закрытого каталога существует, а `keys.json` потерян, первая
настройка не предлагается: это повреждённый комплект, требующий восстановления.
Части сверяются с подписанной описью после расшифрования, чтобы не смешать
разные публикации при обновлении ветки во время чтения.

## Устройство и офлайн

Исходный пароль больше не хранится в localStorage. Для сохранённого входа
IndexedDB содержит неизвлекаемый CryptoKey и зашифрованную копию своего набора;
localStorage — только указатель роли. Публичный кэш очищается списком
разрешённых полей даже при чтении старой локальной копии.

При наличии сети текущий конверт сверяется до восстановления прав. Изменение
или отсутствие ключа снимает вход; ошибка проверки не подменяется отсутствием
сети. Без сети допускается только расшифрование своей ранее сохранённой копии.
Узнать об отзыве без связи невозможно; локальные и уже скачанные данные не
отзываются задним числом. Выход удаляет ключ, закрытую копию и токен публикации
с устройства. Старый пароль из прежнего localStorage убирается при переходе.

CryptoKey является локальным средством доступа, а не защитой от пользователя
разблокированного устройства или вредоносного кода того же origin. CSP
запрещает inline-скрипты и объекты; это дополнительная мера, а не доказательство
отсутствия XSS. Один общий пароль роли не заменяет индивидуальные учётные
записи и серверную авторизацию.

## Импорт и сохранность

Первая строка данных не используется как продолжение заголовка, кроме
распознанной строки подзаголовков. Неизвестный явно указанный код в справочнике
штрихкодов не подменяется совпадением имени. Разные коды одного имени не
склеиваются; неоднозначное имя не выбирает последний товар. Повтор прайса
сохраняет фото и дополняет массивы штрихкодов и поставщиков.

Автоматическое удаление «дублей» при входе отключено. Ручное удаление допускает
только одинаковый непустой код, одинаковые реквизиты и отсутствие ссылок из
цен/заказов/заявок. Совпадение названия и штрихкода не доказывает тождество.
Потерянные в Excel ведущие нули восстановить автоматически нельзя; выгружать
идентификаторы текстом. Реальные файлы магазина на тестовые не заменяются.

## Проверки и ограничения выпуска

`node catalog/tests/security-node.js` — настоящие операции Web Crypto на
фикстурах, независимость ключей, отказ чужому ключу, привязка назначения,
восстановление/отзыв/офлайн и очистка устройства. До исправления исходный
код проваливал 7 из первых 9 проверок.

`publish-parts.js` — браузерный проход публикации, изменения одной записи,
сохранения данных, смены паролей, реального IndexedDB, офлайн и CSP.
`import.js` — повтор импорта, фото/штрихкоды, заголовок и конфликт кодов.
Остальные наборы запускаются через `catalog/tests/run.js` вместе с синтаксисом
и проверкой модулей. Прогон не использует настоящие пароли, токены и данные.
Фикстуры подменяют также `data/index.json` и блокируют чтение непредусмотренных
частей: наличие файлов магазина в checkout не меняет тестовый набор.

История публичного Git может содержать прежние шифртексты и конверты. Новые
ключи закрывают будущие версии от старого ключа; удалить уже скачанные копии
невозможно. Этот выпуск не переписывает историю репозитория и не меняет его
видимость: такие действия требуют отдельного плана сохранения доступа.
