> сотруднику без входа он полезен сразу. Все остальные деньги — за паролем.

## Какую проблему решаем

У части товаров нет штрихкода (бургеры, хот-доги, выпечка, весовой товар).
Кассир знает коды наизусть, но если за кассу сел сотрудник зала — путаница:
какой код у какого хот-дога. **Решение:** сотрудник открывает ссылку, находит товар
по фото или названию — видит все коды и правильно пробивает на кассе.

## Как это работает

### Сотрудник (по ссылке, без регистрации)
- Поиск как в Яндексе: понимает опечатки, часть слова, поиск по коду. Результат — картинками
- Группы товаров для поиска глазами. Товары без штрихкода помечены: «пробивать по коду»
- Карточка товара: все фото (листаются), название как в кассе, крупно код кассы,
  артикул, штрихкод, отдел, примечание. Любой код копируется одним тапом
- Работает и при плохом интернете: последняя версия каталога хранится на телефоне

### Владелец (один админ-аккаунт: email + пароль)
- Вход → появляются кнопки добавления и редактирования
- Добавить товар с телефона: сфотографировал (несколько фото), вписал название и коды,
  выбрал группу → сохранил. Сразу видно всем
- **Изменять можно всё сохранённое:** название, коды, группу, примечание; фото —
  добавить/удалить/заменить; товар — удалить целиком. С телефона и компьютера одинаково
- Группы товаров владелец создаёт/переименовывает/удаляет сам прямо в приложении
- Без входа в админ-аккаунт — только просмотр

### Чего каталог НЕ показывает без входа
❌ Цены, остатки, деньги, контакты поставщиков — по ссылке может зайти кто угодно.
Эти данные видны только после входа сотрудника (раздел «Сравнение цен» ниже).

## Сравнение цен и контакты поставщиков (дополнение 2026-07-11, ✅ утверждён — «Делай 2, 8»)

**Зачем:** сотрудник сам видит, у какого поставщика товар дешевле, и сразу
связывается с ним. Заказы внутри приложения не делаем — владелец решил, что не нужно.

### Как работает
- **Вход — одна форма для всех** (решение владельца 2026-07-11): программа сама
  определяет права по аккаунту. Сотрудник вводит только пароль магазина; админ — свой
  пароль (email спрашивается один раз, дальше устройство узнаёт его само). Без входа
  цен и контактов не видно — ссылка публичная. Вошёл раз — телефон помнит вход
- **Цены поставщиков** берутся из того же импорта 1С «Текущие цены поставщиков»:
  вручную вбивать ничего не нужно, каждый импорт обновляет цены и их даты
- **Сравнение в карточке товара:** поставщики отсортированы по цене, самая низкая
  подсвечена зелёным «✓ выгоднее». Дата рядом с ценой — **последнее поступление
  товара у этого поставщика с этой ценой** (из колонки даты отчёта 1С): цена та же,
  поступление свежее → дата обновляется; цена изменилась → новая строка истории
- **Контакты поставщика:** телефон, контактное лицо, примечание — заполняет админ;
  сотрудник в списке поставщиков и у цены видит кнопки «позвонить» / «WhatsApp»
- **История цен (одобрено владельцем):** каждый импорт добавляет цены с датой, старые
  не стираются. У цены — стрелка «↑ 8 %» если подорожало, «↓» если подешевело;
  тап по строке раскрывает историю. Видно, когда пора менять поставщика
- **Единица продажи (одобрено владельцем):** из колонки «Ед.» импорта 1С — шт / кг /
  упак. Показывается в карточке («Продаётся: шт») и меткой в списке
- **Продажи и «Ходовые товары» (просьба владельца 2026-07-11):** админ загружает отчёт
  «Продажи» из 1С (есть колонка даты — раскладывается по дням само, нет — админ задаёт
  дату файла). Все вошедшие видят «🔥 Ходовые товары»: сегодня / 7 дней / 30 дней /
  свой период — топ по количеству, с фото, штуками и суммой; тап открывает карточку
- **Один аккаунт на всех сотрудников:** вход запоминается на устройстве до нажатия
  «Выйти»; через staff@waymarket.ru одновременно работают десятки телефонов —
  у каждого свой сеанс. Считает топ база, а не телефон — быстро и на 50 сотрудниках
- **Увольнение сотрудника (2026-07-11):** админ в приложении меняет пароль магазина —
  все устройства сотрудников выходят из системы (≤ 1 часа); есть кнопка «только
  выгнать устройства» без смены пароля
- **Экономная история цен (2026-07-11):** база записывает цену только когда она
  изменилась — ежедневный импорт не плодит одинаковые строки (проверено тестом:
  та же цена → 0 записей, новая → 1)
- **Приложение на телефоне (2026-07-11):** манифест + офлайн-скрипт — каталог
  ставится на главный экран как приложение; без связи работает каталог целиком
  и цены недавно открытых товаров (стираются при выходе из аккаунта)

### Дизайн — на чём основан (исследования удобства)
| Правило | Откуда | Что делаем |
|---------|--------|-----------|
| Большие цели для пальца | Закон Фиттса; исследование Хубера: 75 % касаний — большим пальцем | Кнопки от 48 px; «позвонить»/«WhatsApp» — крупные, внизу карточки |
| Меньше выбора — быстрее решение | Закон Хика | Один экран — одно действие; сравнение цен — короткий список, не таблица-простыня |
| Лучший вариант подсвечивать, а не заставлять сравнивать в уме | Baymard Institute — крупнейшие исследования интернет-магазинов | Зелёная метка «✓ выгоднее» у самой низкой цены |
| Показывать, что происходит | 10 эвристик Нильсена (Nielsen Norman Group) | Дата у каждой цены; после входа видно, что режим сотрудника включён |
| Узнавание вместо запоминания | Эвристики Нильсена | Фото товара везде; контакты — в карточке поставщика, где их ищут |

Стиль прежний: зелёный акцент Way Market, светлая/тёмная тема, крупный текст.

### Что добавилось в базе (миграции `setup/ОБНОВЛЕНИЕ-2.sql`, `-3.sql`)
- продажи по дням: товар × дата × количество × сумма + функция подсчёта топа за период
  (считает база, телефон получает готовый список)
- контакты поставщика: телефон, контактное лицо, примечание (отдельная таблица)
- таблица цен с историей: товар × поставщик × цена × дата (заполняет импорт 1С)
- у товара: единица продажи (шт / кг / упак)
- список администраторов: сотрудники читают цены и контакты, менять каталог — только админ
- вход сотрудников: служебный аккаунт `staff@waymarket.ru`, сотрудник вводит только
  пароль магазина (порядок включения — в `setup/НАСТРОЙКА.md`)

### Категории и подгруппы (2026-07-12)
Группы из 1С (их 200+) программа сама раскладывает по ~13 понятным **категориям**
(Напитки, Молочное, Сладости, Хлеб и выпечка, Мясо и рыба, Дом и химия, Красота и
гигиена, Бакалея, Снеки, Заморозка, Овощи и фрукты, Детское, Прочее) — по названию
группы. Верхний ряд чипов — категории; выбрал категорию — второй ряд показывает её
подгруппы (исходные группы 1С). Новые группы при импорте распределяются автоматически.

### Фото из Excel по ссылкам (2026-07-12)
Меню админа «🖼 Фото из Excel»: файл, где колонка со ссылкой на фото + колонка со
штрихкодом/кодом/названием. Товары находятся по штрихкоду → коду → точному названию,
фото показывается **по ссылке** (не перезаливается в хранилище). Отдельно есть
«🌐 Фото по штрихкодам» — автопоиск в интернете (Open Food Facts).

### Контакты поставщика в карточке товара (2026-07-12)
После входа под каждым поставщиком в карточке товара — имя контактного лица,
кнопки «📞 позвонить» и «💬 WhatsApp», примечание, и «показать все товары поставщика».

### Продажи в карточке товара — для заказа (2026-07-12)
После входа в карточке товара — блок «Продажи» в **штуках** (не деньгах):
за 7 дней · за 30 дней · среднее в день. Берётся из загруженных продаж,
кэшируется на телефоне (видно без связи), для непродающихся товаров скрыт.
Сотрудник и админ сразу видят, ходовой ли товар и сколько заказывать.

### Быстрая загрузка и свежие данные (2026-07-12)
- **Кэш в IndexedDB** (не localStorage): каталог на 16 тыс. товаров ~8 МБ не влезал
  в localStorage (~5 МБ) и тихо не сохранялся — оттого пустой экран и долгая загрузка
  каждый раз. Теперь кэш реально хранится, повторный заход мгновенный, работает офлайн.
- **Докачка (delta-sync):** при заходе тянутся только изменившиеся товары (по дате
  изменения) + быстрая сверка количества (ловит удаления) — обычно 2 запроса вместо 17.
- **Прогрессивная загрузка:** первая страница товаров показывается сразу (~0,3 с),
  остальное догружается в фоне — экран не пустует.
- **Библиотека базы — локально** (не с чужого CDN): быстрее старт, работает офлайн.
- Индекс `idx_products_updated` — миграция `setup/ОБНОВЛЕНИЕ-5.sql`.

### Поставщики и цены в карточке товара (2026-07-12, редизайн)
Единый раздел «Поставщики и цены»: **все** поставщики товара, у каждого — цена и
**дата последнего поступления** по этой цене; самая низкая помечена «✓ выгоднее»
со стрелкой тренда; поставщик без цены — «цена не указана». Каждая строка
**кликабельна** → карточка поставщика: контактное лицо, крупные кнопки
**«📞 Позвонить»** и **«💬 WhatsApp»**, телефон, примечание, цена+дата, история
цены, «показать все товары поставщика»; у админа — «изменить контакты». Цены и
контакты — только после входа (закрыто правами базы).

### Инструменты сотрудника зала (2026-08-21 … 22)
Всё, что ниже, работает **на телефоне сотрудника**: писать в общий каталог может
только владелец, поэтому записи лежат на устройстве и одной кнопкой уходят ему
текстом (WhatsApp, сообщение). У владельца то же самое сохраняется сразу в каталог.

- **Проверка ценника крупно** — сканируешь штрихкод, в окне камеры крупно
  название, цена и код. Карточка не открывается: она перекрывала бы камеру.
- **Сканирование подряд** — камера не закрывается после каждого товара.
  Режим выбирается переключателем: «Товар» / «Ценник» / «Закончилось».
- **«Мои частые товары»** — лента на главной: то, что этот телефон открывает
  чаще всего (хот-доги, выпечка, весовое) — в одно касание.
- **Плашка «что ждёт сегодня»** вверху главного экрана: сколько поставок
  приезжает сегодня и на какую сумму, сколько просрочено; тап — к заказам.
  Нет дел — нет плашки.
- **Вкладка «Работа»** в нижней панели — дела смены в одном месте: заказы
  (сколько поставок на неделе и на какую сумму), просроченные поставки,
  «закончилось на полке», сравнение, сканер. На вкладке значок: сколько дел
  ждёт. Без входа экран объясняет, что это для сотрудников, и предлагает войти.
- **Заказы поставщикам** — у кого, когда заказали, когда придёт, кто заказал и
  на какую сумму. Календарь в двух видах: **неделя** (столбики по дням, сумма
  за день и за неделю) и **месяц** (вся сетка дней с суммами, итог за месяц;
  тап по дню открывает его неделю). Кнопка «Сегодня» возвращает к текущей
  неделе. **Просроченные** поставки (день прихода прошёл, «пришёл» не отмечен)
  помечены красным и собраны отдельным блоком, чтобы заказ с прошлой недели
  не потерялся. В заказе можно перечислить **что именно заказали** (позиции
  с количеством) — по коду подставляется товар из каталога, чего в каталоге
  нет, записывается как есть; позиции необязательны, заказ «как обычно»
  остаётся одной суммой. Из списка «закончилось» позиции подставляются сами.
- **Сравнение товаров** — до 8 позиций рядом: закупка за штуку, у кого она,
  розница, наценка, остаток; самая выгодная закупка зелёным.
- **«Закончилось на полке»** — кнопка в карточке или обход зала с камерой в
  режиме «Закончилось». Список сам раскладывается по поставщикам, из группы
  сразу оформляется заказ (поставщик и перечень подставлены), заказанное
  помечается, чтобы не заказали дважды, и через две недели исчезает само.
- **Быстрые действия с ярлыка** — долгое нажатие на значок приложения на
  главном экране телефона: «Сканер» и «Закончилось» открываются сразу.

> Пересчёт остатков (инвентаризация) владельцу **не нужен** — 2026-08-22,
> сделанный экран убран. Не возвращать без отдельной просьбы.

### Скорость на слабых телефонах (аудит 2026-08-26)
Замеры на процессоре **в 6 раз медленнее обычного** (это и есть бюджетный
Android), каталог 17 000 товаров:

| Что | Было | Стало |
|-----|------|-------|
| Первые товары на экране | 1666 мс | 441 мс |
| Весь каталог загружен | 6915 мс | 1060 мс |
| Поиск словом | ~6 с (на каждую букву) | 439 мс |
| Поиск по коду | 401 мс | 287 мс |
| Открытие карточки | 228 мс | 93 мс |
| Самая длинная заминка (телефон не отвечает) | 3788 мс | 394 мс |

Что было сделано:
- **поисковый индекс не считается заранее для всех товаров** — производные
  строки считаются по требованию; появился указатель «начало слова → товары»,
  он строится порциями в свободную минуту, и поиск считает кандидатов, а не
  весь каталог; разбор опечаток — отдельным проходом с дешёвой отбраковкой;
- **офлайн-копия отдаёт оболочку сразу**, свежую версию догружает в фоне
  (раньше каждый заход ждал ответа сервера по двум десяткам файлов);
- **разборщик Excel (310 КБ сжатых) не качается при первом заходе** всем
  подряд — он нужен только владельцу, сохраняется при первом использовании;
- **разбор файлов 1С — в отдельном потоке**, экран во время загрузки живой;
- **экономный режим** на телефонах с 4 ГБ памяти и меньше: «матовое стекло»
  (размытие под шапкой и окнами) заменяется затемнением — именно оно
  пересчитывалось каждый кадр и давало рывки при прокрутке;
- подсказка «поставить на главный экран» — так каталог запускается быстрее.

Планку держат проверки `tests/speed.js` (скорость на медленном процессоре),
`tests/offline.js` (работа без связи и обновления), `tests/search-quality.js`
(выдача поиска не меняется от ускорений).

### Деньги и отказы (2026-08-27)
- **Суммы везде с разделителями разрядов** — 1 250 000, а не 1250000. Не только
  там, где показываются, но и **в полях ввода**: число разбивается по ходу
  набора, а сохраняется настоящее число. Количества в отчётах тоже разбиты.
- **Отказ публикации объясняется словами.** Просроченный ключ GitHub, не
  найденная ветка, «слишком часто», сбой GitHub — каждому своя понятная фраза
  и плашка с действием («Нажми, чтобы вставить новый ключ»). Записанное всегда
  остаётся на телефоне, даже если опубликовать не вышло.

## Техника

| Что | Где | Цена |
|-----|-----|------|
| Код приложения | Папка `catalog/` в репозитории; публикуется на GitHub Pages по адресу `…/Auron/catalog/` (при желании владельца переносится в отдельный репозиторий со своей ссылкой — 5 минут) | ₽0 |
| Данные и фото | Файлы в репозитории на GitHub (витрина открыто, остальное зашифровано) | ₽0 |

**Файлы:** `catalog/index.html` + `catalog/styles.css` + `catalog/js/app.js` + `catalog/js/config.js` (адрес и ключ базы) + `catalog/setup/schema.sql` (создание таблиц одним запуском) + `catalog/setup/НАСТРОЙКА.md` (пошаговая инструкция для владельца, 10 минут).

## Что осталось сделать владельцу
1. Опубликовать каталог со своего телефона — данные на GitHub ещё в старом
   формате (одним файлом), после публикации станут кусками и будут грузиться
   заметно быстрее
2. Открыть каталог заново на каждом рабочем телефоне — приложение обновится
   само, но первый заход после обновления нужен, чтобы новая версия прижилась
