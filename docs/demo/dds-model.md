# Как устроен отчёт ДДС владельца

Разобрано по **настоящим формулам** из файла (не по названиям колонок).
Это модель дня магазина, которую нужно повторить в приложении.

## Что вводится руками, а что считается

| Вводит человек | Считает таблица |
|---|---|
| Дата, смена | Наличка в кассе |
| Наличная торговля | Расхождение кассы |
| Онлайн торговля | На закуп |
| Иман (изъятие хозяина) | Общая торговля |
| Закуп за наличку офисом | Валовая прибыль (25%) |
| Выплата долга офисом | Прибыль |
| Закуп товаров в долг | Общий закуп |
| Списание продукта | Расхождение выплат офиса |
| Комиссия банка, обед, ГСМ, расходники | Долг поставщикам |
| Зарплата, аренда, коммунальные, налог | |

## Формулы, как они есть

**Общая торговля за сутки**
```
Общая торговля = наличная(день) + наличная(ночь) + онлайн(день) + онлайн(ночь)
```

**Наличка в кассе после смены**
```
Наличка = наличная торговля − выплата кассы − Иман − перевод
```

**Расхождение кассы**
```
Расхождение = наличная торговля − выплата кассы − перевод − Иман − наличка
```
По построению всегда ноль — это самопроверка, что ничего не потерялось.
За июль оно и равно нулю по всем 62 сменам.

**Валовая прибыль**
```
Валовая прибыль = общая торговля × 0,25
```

**Прибыль дня**
```
Прибыль = валовая прибыль
        − расходники − ГСМ − комиссия банка − обед − списание
        − Иман(день) − Иман(ночь)
        − перевод(день) − перевод(ночь)
        − зарплата − аренда − коммунальные − налог
```

**Сколько можно потратить на закуп**
```
На закуп = общая торговля − валовая прибыль − выплаты кассы − переводы
         − Иман − прибыль − списание − комиссия − расходники − обед
```
Смысл: из выручки убираем свою маржу и все траты — остаётся
себестоимость проданного, её надо вернуть в товар.

**Расхождение выплат офиса**
```
Расхождение = на закуп(день) + на закуп(ночь)
            − закуп за наличку − выплата долга − закуп в долг
```
Сколько **могли** потратить минус сколько **реально** потратили.
Минус означает: потратили больше, чем позволяла выручка.

**Долг поставщикам** (накопительный остаток)
```
Долг сегодня = долг вчера − выплата долга + закуп в долг
```

## Расшифровка проверена, а не предположена

Я пересчитал первые пять дней июля по формулам выше и сверил с тем, что
стоит в таблице владельца: общая торговля, валовая 25%, прибыль и
наличка — **20 значений из 20 сошлись до рубля**. Значит модель понята
верно и её можно переносить в код.

## Главное, что показывают формулы

**1. Прибыль считается по нормативу, а не по факту.**

`Валовая прибыль = торговля × 0,25` — это допущение, что наценка ровно
25%. Настоящие закупочные цены в расчёт не берутся.

Приложение считает иначе — по настоящим ценам из 1С — и даёт наценку
**29,5%** и рентабельность **22,8%**. Отсюда и расхождение прибыли за
июль: 1 507 547 ₽ по отчёту против 1 900 853 ₽ по разнице доходов и
расходов.

Обе цифры не ошибочны, это два разных вопроса:
- 25% — «сколько я планирую зарабатывать»;
- 29,5% — «сколько наценки стоит в ценниках на самом деле».

**2. Расхождение выплат офиса за июль — минус 10 млн ₽.**

Формула честная: столько магазин потратил на закуп сверх того, что
позволяла выручка. Это ровно та же картина, что и в остальных данных:
закуп 18,1 млн против торговли 13,2 млн, долг поставщикам вырос на
0,9 млн, на складе лежит 2,36 млн неликвида.

**3. Иман и переводы вычитаются из прибыли.**

То есть изъятия хозяина в этой модели уменьшают прибыль магазина, а не
считаются распределением уже заработанного. Это выбор владельца, но
знать о нём стоит: при большом изъятии прибыль просядет, хотя магазин
сработал так же.

## Что это значит для приложения

День в магазине выглядит так:

1. Утром принимается смена (в приложении будет **имя кассира** — в
   таблице его нет).
2. В течение дня пишутся выплаты торговым представителям.
3. Вечером до закрытия вносятся: закуп за наличку, выплата долга, закуп
   в долг, списание, комиссия, обед, ГСМ, расходники.
4. Закрывается смена: наличная и онлайн торговля, Иман.
5. Приложение само считает наличку, расхождение кассы, на закуп,
   прибыль и новый долг поставщикам.

Всё, что нужно для этого, в приложении уже есть по частям: смены, касса,
выплаты, долги, списания. Не хватает **сведения дня по этим формулам** и
экрана закрытия смены, который спрашивает ровно эти цифры.
