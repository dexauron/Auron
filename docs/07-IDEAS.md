| Идея | Причина |

## 💬 Большая идея: общение + задачи + портал торговых представителей (v2+)
_Записано по просьбе владельца. Крупный модуль на будущее — НЕ v1._

**1. Внутренний мессенджер для сотрудников.**
- Сотрудники общаются между собой прямо в приложении (как мессенджер).
- Постановка задач друг другу и контроль: какие задачи выполнены, какие ещё нет.
- Владелец/администратор видит статусы задач.

**2. Портал торгового представителя (ТП) / поставщика.**
- ТП сам через приложение оформляет: «заказал на такую-то сумму, придёт такого-то числа».
- Это автоматически попадает администратору/бухгалтеру — им НЕ нужно вручную записывать заказ и выплату.
- Можно запланировать выплату и заказ прямо в переписке с ТП.

**3. Данные о торговых точках и поставщиках.**
- Контакты ТП и поставщиков, привязка к магазинам (торговым точкам).
- По каждому: что заказали (сумма, дата ожидаемого прихода) и что пришло по факту.

**4. Приёмка по факту сотрудником магазина.**
- Сотрудник отмечает фактический приход: сумма накладной С УЧЁТОМ всех минусов (возвраты, недовоз, брак) — т.е. реальная сумма.
- Сверка «заказано ТП» ↔ «пришло по факту».

**5. Медиа в общении.**
- Голосовые сообщения, фото, видео, файлы.

**Почему на будущее:** требует настоящего backend (реалтайм-чат, хранилище медиа, аккаунты ТП, права) — на Google-таблицах не тянется. Включается на этапе перехода на backend (см. `08-ARCH-OPTIONS.md` + `10-BACKEND-SKILLS.md`). Тесно связано с существующими «Заказами» и «Выплатами» — при реализации переиспользовать их.

## 🔗 Большая идея: 1С-интеграция + мульти-аренда + собственный ИИ (v2+)
_Записано по просьбе владельца. Стратегический вижен, НЕ v1._

**1. Интеграция с 1С + мульти-аренда (одно приложение — много ролей и организаций).**
- Приложение интегрируется с 1С (данные тянутся автоматически, не вручную).
- **Поставщики** получают это же приложение, настроенное под их нужды.
- **Торговые точки/магазины**: у всех сотрудников — своя настройка под роль, задачи и нужды (роли уже есть в v1).
- Сотрудники общаются и переписываются внутри приложения (см. идею «мессенджер + портал торгпредов»).
- **Данные видны только тем, кому нужны и у кого есть доступ** — строгая ролевая изоляция (в v1 UI-скрытие + серверные проверки; для настоящей изоляции — backend, см. `08`).

**2. Собственный ИИ на своём сервере.**
- Не внешний API, а свой ИИ на собственном сервере (данные не уходят наружу).
- Обучается на данных, анализирует, помогает: пользователям (советы, автоматизация), разработчику (развитие приложения).
- Цель: приложение само развивается, остаётся полезным, удобным, простым.
- Связано с `09-AI-VISION.md` (Auron как ИИ) и текущим самообучением («Мозг»: норма расходов/выручки/закупок). Это его продолжение на настоящем backend.

**Почему на будущее:** мульти-аренда, аккаунты поставщиков/торгпредов, реалтайм-общение и собственный ИИ-сервер требуют перехода с Google-таблиц на настоящий backend (`08-ARCH-OPTIONS.md`) и профильных навыков (`10-BACKEND-SKILLS.md`). В v1 закладываем совместимую основу (роли, права, самообучение), чтобы переезд был эволюцией, а не переписыванием.

## 🧰 Внешние ресурсы, предложенные владельцем (разобраны 30.07.2026)

Записаны, чтобы не потерялись. Ниже — не рекламные описания, а решение по
каждому с причиной. Общий вывод: качество дизайна в этом проекте выросло
не от библиотек, а от двух бесплатных вещей — снимков экрана (скил `look`)
и шести образцов, которые прислал владелец.

| Ресурс | Решение | Почему |
|---|---|---|
| **grill-me** (mattpocock/skills) | взять ИДЕЮ | Заставляет выяснить детали до кода. У нас это записано правилом «обсудили → показал → делай», но правило дважды не сработало там, где сработал скрипт. Берём процедуру, не репозиторий: там два десятка скилов, а много перекрывающихся скилов ухудшают выбор. |
| **ui-ux-pro-max-skill** | не берём | Каталог из 84 стилей и 192 палитр нужен тому, кто ещё не выбрал. Владелец выбрал — тёмная тема с зелёным акцентом по своим образцам. Плюс ставится через npm, кладёт свои файлы в `.claude/`, тянет Python-скрипты, рассчитан на React/Vue. У нас один HTML-файл без сборки и правило не тянуть чужие инструкции для ИИ не глядя. |
| **MotionSites** | идеи да, код нет | Библиотеки анимаций написаны под React и сборщики — копировать в наш файл нечего. Полезно как источник примеров: владелец показывает движение, которое нравится, я повторяю руками. |
| **GetLayers** | не под задачу | Промты для генерации изображений не превращаются в вёрстку. |
| **Higgsfield** | не берём, платно | Приложению для учёта денег в магазине не нужно ни одного сгенерированного фото или видео — нет ни одного экрана, где они бы стояли. Вернуться, если понадобится страница-визитка или реклама Auron. |

**Правило, выведенное отсюда:** прежде чем ставить внешний набор, спросить —
он даёт ВЫБОР (каталог) или ЗРЕНИЕ (обратную связь о результате)? Каталог
после принятого решения только спорит с ним. Зрение помогает всегда.
