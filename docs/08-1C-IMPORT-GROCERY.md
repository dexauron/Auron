## 1. Что берём из модели данных Дзен Мани
Публичная модель Дзен Мани (их открытое API) строится на сущностях:
Account (счёт), Tag (категория), Merchant (получатель/контрагент), Transaction (операция),
Reminder (план/повтор), Budget (бюджет), Instrument (валюта), Company (банк).
Синхронизация — через **Diff** (инкрементально по serverTimestamp).

Как ложится на наш `webapp`:

| Дзен Мани | У нас сейчас | Доработка |
|-----------|--------------|-----------|
| Account | СЧЕТА | ✅ есть |
| Tag (категория) | НАСТРОЙКИ.CATS | ✅ есть |
| Transaction | БАЗА | ✅ есть |
| Merchant (контрагент) | Поставщики/ДОЛГИ | ✅ есть |
| Reminder (план/повтор) | РЕКУРРЕНТНЫЕ | ✅ есть |
| Budget | BUDGET в НАСТРОЙКАХ | ✅ есть |
| Instrument (валюта) | RUB (фикс) | позже, если нужно |

Вывод: модель уже близка к Дзен Мани. Главное недостающее — **товарный учёт** и **импорт 1С**.

## 2. Как «понимать 1С» — реальные форматы обмена
1С не один формат. Практично для магазина — три источника:

### а) Банковская выписка — `1CClientBankExchange` (он же `kl_to_1c.txt`)
Текстовый формат-стандарт фирмы «1С» для обмена с «Клиент-банком».
Структура: служебная шапка (версия, кодировка DOS/Windows, отправитель, даты, расчётные
счета) → секции остатков/оборотов → документы (платёжки) с реквизитами
(номер, дата, сумма, плательщик, получатель, назначение).
**Что даёт:** автоматический импорт приходов/расходов по расчётному счёту → строки в БАЗА.
Самый ценный и простой для парсинга формат.

### б) Excel/CSV отчёты из 1С (Розница / Бухгалтерия)
Владелец выгружает отчёт в Excel:
- **Отчёт по продажам / чекам ККМ** → выручка по дням/товарам.
- **ОСВ** (оборотно-сальдовая ведомость) → остатки/обороты по счетам.
- **Остатки товаров**.
**Что даёт:** «переводчик» читает структуру отчёта и складывает в БАЗА/товары.
Минус: у каждой конфигурации 1С своя колоночная структура → парсер настраиваемый
(пользователь сопоставляет столбцы — Smart Paste).

### в) Номенклатура товаров — `CommerceML` (XML: import.xml / offers.xml)
Стандарт выгрузки товаров/цен из 1С (используется в 1С-Bitrix).
**Что даёт:** справочник товаров с ценами → товарный учёт.

**Приоритет (по решению владельца — всё через Excel):**
главный канал — **универсальный импорт Excel-файла из 1С** (отчёты, остатки, продажи).
Формат `1CClientBankExchange` и CommerceML — опционально, позже.

## 3. Розничная бухгалтерия (что добавляем под продуктовый)
> ⚠️ ОБНОВЛЁННОЕ РЕШЕНИЕ ВЛАДЕЛЬЦА (2026-06-30): **товарный справочник теперь
> ВНУТРИ приложения.** 1С остаётся источником (учёт ведётся там), но данные из
> Excel-выгрузок (Цены/Продажи/Остатки/Закупки) **накапливаются и сохраняются**
> в приложении, и по ним строится аналитика. 1С = источник, приложение = финансы
> + товарная аналитика с собственной базой.

Реализация:
- Лист `ТОВАРЫ` (справочник, upsert по штрихкоду/наименованию) + `ЦЕНЫ_ИСТ` (история цен).
- Экран «Товары» (Настройки → Товары и аналитика): метрики, рост цен поставщиков,
  топ по прибыли, низкая наценка, ходовой товар, неликвид, поставщики + поиск по справочнику.
- Заполняется через экран «Импорт 1С»: при распознавании отчёта — кнопка
  «Сохранить в справочник товаров».

Значит:
- **Товары/остатки/себестоимость** — храним снимок в приложении из Excel-выгрузок 1С (сам учёт — в 1С).
- **Поставщики, долги по накладным** — ✅ есть.
- **Кассовые смены / Z-отчёты / слепая инкассация** — ✅ есть.
- **ОСВ-подобная сводка** (приход/расход/остаток по счетам) — есть в Аналитике.
- **Налоги** (УСН / патент) — расчёт и календарь (позже).

## 4. Фазовый план (по одному, с проверкой)
1. **Универсальный импорт Excel из 1С** — экран «Импорт 1С»:
   загрузка `.xlsx`/вставка таблицы → сопоставление столбцов (дата/тип/категория/
   сумма/счёт/комментарий) → предпросмотр → запись в БАЗА с дедупом.
   Работает для ЛЮБОГО отчёта 1С (продажи, обороты, движения).
2. **Шаблоны сопоставления** — запоминаем разметку столбцов под конкретный отчёт
   1С, чтобы в следующий раз импортировать в один клик.
3. **Импорт остатков** — отдельный режим: Excel-остатки 1С → корректировка
   остатков счетов / справочная сводка.
4. **ОСВ-сводка + налоги** (УСН/патент) на основе импортированных данных.
5. (Опц.) Импорт банковской выписки `1CClientBankExchange`.

Каждая фаза = отдельная ветка задач, проверка в превью, коммит.
Товарный учёт в приложении — НЕ делаем (см. §3).
