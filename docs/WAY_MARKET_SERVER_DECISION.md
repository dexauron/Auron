# Решение владельца: компьютер магазина — центральный сервер

Подтверждено сообщением владельца 17.10.2026: Windows Server установлен на выделенном компьютере, подключение с другого компьютера по RDP работает; приложение и данные следует размещать на этом сервере.

## Целевая архитектура

- Центральный узел: AURON-SERVER, известный локальный IP 192.168.1.132 (резервирование DHCP подтверждено ранее). Node.js-сервис и единственная основная база работают на нём.
- Внутренние клиенты: браузеры компьютеров/телефонов → защищённый API → проверка пользователя/роли/магазина → доменные операции → SQLite на локальном SSD сервера. Сам файл SQLite не открывается по SMB и не копируется каждому клиенту как самостоятельная основная база.
- RDP нужен для администрирования и первоначального теста, не является способом выдачи приложения всем сотрудникам. Пользователи приложения не получают учётную запись администратора Windows.
- Подтверждённые данные находятся на сервере; будущие клиентские офлайн-черновики требуют отдельной схемы синхронизации и не являются проведёнными документами до принятия сервером. В первой версии офлайн-очереди нет.
- Публичный каталог — отдельная сборка/публичный экспорт по белому списку, без прямого доступа к финансовой базе. Место публичного размещения определять отдельно от внутреннего сервера; не открывать внутренние API покупателям.
- Касса, прибыль и проверки работают без облачного ИИ. Запросы в OpenRouter — отдельный разрешённый канал: только минимальные разрешённые данные, с обезличиванием и проверкой маршрута. Нельзя обещать, что внешнему ИИ вообще ничего не передаётся, если его использовать.
- Сервер должен работать постоянно. Выключение/сон/сбой сервера останавливает доступ клиентов. Планируются отдельная служба Windows, выделенная учётная запись, ограниченные права на каталог данных, HTTPS, аудит, ИБП и проверяемые резервные копии вне этого SSD. Это пока не установленные компоненты.

## Что реализовано в 0.3

Добавлен явный Windows-режим `--server-test` и запуск `start-server-test.cmd`. Основная **тестовая** база в нём — `%ProgramData%\WayMarket-Test\cash-test.sqlite`, обычно `C:\ProgramData\WayMarket-Test\cash-test.sqlite`. Путь не меняется при смене интерактивного Windows-пользователя. Это конфигурация кода, не подтверждение установки на реальный сервер.

Старый `start-windows.cmd` продолжает открывать прежнюю пользовательскую тестовую базу. Если обнаружена прежняя база текущего пользователя, а серверной ещё нет, серверный режим отказывается создавать пустую базу вместо старых данных: требуется явный перенос через проверенный архив. Автоматической миграции/слияния нет. Базы других Windows-пользователей автоматически не ищутся.

Сервис по-прежнему слушает **только 127.0.0.1:3210**. До разработки авторизации и изоляции гостевого Wi-Fi не добавляется параметр публикации в LAN. Первоначальный тест — браузером сервера через уже настроенный RDP. Порт роутера и правила Windows Firewall не изменяются. Скрипт запуска не устанавливает службу Windows и не раздаёт права на папку ProgramData.

## Нерешённые вопросы перед реальными данными

1. Изолировать покупателей от касс/сервера/управления роутером; владелец сообщил, что покупатели сейчас используют тот же роутер, проверка изоляции отложена.
2. Встроить авторизацию, роли, независимые подтверждения, аудит, сессии и HTTPS. Только после этого включать браузерный доступ с рабочих устройств.
3. Настроить внешний защищённый носитель/хранилище, расписание и пробное восстановление. Ручной архив уже есть, но не настроен как системная автоматическая копия.
4. Решить лицензию Windows Server: ранее установленная RETAIL-копия была в режиме уведомления, ключ не приобретён. Не считать активацию решённой.
5. Испытать запуск Node.js 24 на реальном компьютере i3-2120/8 ГБ/SSD 238,5 ГБ. Нагрузочная ёмкость не измерена.

## Проверки этого изменения

6 новых тестов конфигурации: сохранение прежнего пути, единая серверная папка при смене пользователя, отказ неверного ProgramData, отсутствие обхода loopback через аргументы, защита от незаметного создания пустой базы вместо прежней и явное открытие существующей восстановленной копии. Вместе — 53 автоматических теста. Тесты Windows-путей выполнены как чистые функции на Linux; реальная Windows ACL/служба/запуск не испытаны.
