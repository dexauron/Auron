# Интерфейс для обычных сотрудников — 17.10.2026

## Решение владельца

Пользователи не обязаны быть профессиональными бухгалтерами. Интерфейс должен помогать человеку перенести данные из документов, увидеть результат и исправить ошибку. Одинаковая полнота функций на телефоне, планшете и компьютере; расположение адаптируется к экрану. Упрощение не означает неизвестные суммы, подставленные нулём, или изменение правил расчёта.

## Реализовано в тестовой 0.5

Вместо длинной одновременной формы — пять шагов: смена, наличные, выплаты, терминал, передача/проверка. Один видимый шаг. На последнем показываются результат и сохранение; на компьютере — две колонки, на телефоне — одна. На телефоне разделы приложения доступны через нижнюю панель, на широком экране через боковую. Крупные поля, системный шрифт, заметный фокус, 44+ px основные цели нажатия, поддержка safe-area и reduced-motion. Пояснения расположены рядом с действием.

На шаге наличных редкие/дополнительные группы раскрываются: размен, прочие движения, способ расчёта. В заголовке группы видно, заполнена ли она. Если обязательные данные пропущены, «Далее» открывает нужную группу, объясняет проблему и переводит фокус к полю. Отметка «указано» означает наличие ввода, не независимую проверку достоверности.

Вместо обязательного набора нулей — кнопка «Не было», для второго отчёта «Нет второго отчёта». Это явное решение человека. Непустая ненулевая сумма не заменяется нулём без вопроса. Неизвестное поле остаётся пустым, недостающие обязательные данные блокируют окончательное сохранение. Денежные поля не используют ноль по умолчанию.

«Вся форма» открывает прежний полный сценарий, без смены расчётного режима. Переходы и раскрытие групп не очищают введённые суммы. Выбор общих/подробных выплат — отдельная настройка; конфликтующие данные не удаляются автоматически, сохранение блокируется с объяснением.

Enter на раннем шаге переводит к следующему, не отправляет скрытую итоговую форму. Сохранение проверяет все шаги и тот же серверный расчёт. История, печать сохранённой версии, проверка архива и старые записи совместимы. Формулы/SQLite-схема версии 0.4 не менялись. При открытии старой смены её способ расчёта не переключается автоматически.

## Подход Apple и самостоятельный стиль

Опора: ясная иерархия, достаточное пространство, последовательность, доступность и постепенное раскрытие подробностей из [Apple HIG — Layout](https://developer.apple.com/design/human-interface-guidelines/layout) и [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility). Сохраняется зелёный акцент Way Market, собственные SVG-иконки и русские подписи. Не использовать непонятные иконки без подписей и декоративную прозрачность в ущерб контрасту. Не загружать системные иконки Apple как универсальный шрифт для всех ОС.

## Кроссплатформенная архитектура и пределы проверки

Клиент — адаптивный HTML/CSS/JavaScript в современном браузере. Системные шрифты и стандартные элементы обеспечивают основу для Windows, Linux, macOS, Android и iOS. Работа через браузер не требует отдельной клиентской сборки для каждой ОС; возможности установки на домашний экран/офлайн и нативные функции требуют отдельной реализации и проверки. Не обещать поддержку буквально любого старого устройства/браузера.

В 0.5 локальный сервис по-прежнему слушает только 127.0.0.1, поэтому responsive-дизайн не означает, что телефон уже подключается к серверу. Доступ по сети и реальная авторизация ещё не реализованы. Данные тестовой установки остаются на выделенном Windows-сервере. Не превращать интерфейсную доработку в несанкционированное открытие порта.

Проверено на Linux/Chromium в размерах 1440×1000, 820×1180, 390×844 и 320×740: последовательный ввод с пустого состояния, ошибки и фокус, явные нули, раскрытие групп, точный результат, сохранение, повторное открытие, исправление с причиной, печать, архив, полная/пошаговая форма. Это проверка адаптивности, не реальные запуски на Android/iPhone/macOS. Safari/WebKit, Firefox, системные экранные дикторы, виртуальные клавиатуры и реальные устройства — отдельная матрица до выпуска. Полный расчётный/серверный набор 71 тест также прошёл.

## Дальнейшие улучшения, пока не реализованы

- После авторизации подставлять имя заполняющего из сессии; выбирать кассу и сотрудника из доступного списка. Не угадывать ответственность по последнему введённому имени.
- Настроить магазин один раз: формат его отчётов, подписи полей, место размена и правила возвратов; зафиксировать версию настройки и проверить на контрольном примере. Обычный сотрудник не должен ежедневно выбирать бухгалтерскую методику.
- Черновики, безопасное продолжение после сбоя, проверенный импорт/OCR с подтверждением исходных сумм; ни распознавание, ни предварительное заполнение не считаются независимой проверкой.
- Пользовательская проверка с обычным сотрудником: найти нужную сумму в отчёте, внести её, исправить ошибку, закончить сдачу без подсказок разработчика. Комфорт и скорость ещё нельзя считать подтверждёнными по одному визуальному тесту.
