# Ключ подписи приложения — как создать и куда положить

## Главное правило: ключ никому не показывают

**Мне ключ передавать не нужно и не следует.** Кто владеет ключом —
может выпустить приложение от вашего имени: с вашим значком, с вашим
названием, и телефоны людей примут его как обновление настоящего Auron.

Поэтому порядок такой:
- **ключ создаёте вы**, на своём компьютере;
- **кладёте его в хранилище секретов GitHub** — туда нет доступа ни у
  меня, ни у кого-либо ещё, кроме вас;
- **говорите мне «положил»** — я включаю в сборке нужный блок, не видя
  самого ключа.

Так работают и в компаниях: ключ знает один-два человека, разработчики
его не видят.

---

## Шаг 1. Создать ключ — подробно, для тех, кто этого не делал

Займёт минут пятнадцать. Программировать не нужно: вы вводите одну
строку и отвечаете на семь вопросов.

### 1.1. Поставить Java

Ключ создаёт программа, которая идёт вместе с Java. Java — бесплатная.

1. Откройте сайт **adoptium.net**
2. Там большая синяя кнопка **«Latest LTS Release»** — нажмите
3. Скачается файл. Запустите его
4. Жмите **Next → Next → Install → Finish**. Ничего менять не надо

> **Важно для Windows.** В середине установки будет список
> с галочками. Найдите строку **«Set JAVA_HOME variable»** и включите
> её (нажмите на крестик слева → «Will be installed»). Без этого
> команда потом не найдётся.

Если у вас уже стоит Android Studio — Java есть, этот пункт пропустите.

### 1.2. Открыть окно для команд

**Windows:**
1. Нажмите клавишу **Windows** (между Ctrl и Alt)
2. Наберите: `cmd`
3. Нажмите **Enter**

Откроется чёрное окно с белым текстом. Это оно.

**Mac:**
1. Нажмите **Cmd + пробел**
2. Наберите: `Терминал`
3. Нажмите **Enter**

### 1.3. Перейти в папку, где будет лежать ключ

Чтобы потом не искать файл по всему компьютеру, положим его на
Рабочий стол. Введите в окно **ровно эту строку** и нажмите Enter:

**Windows:**
```
cd %USERPROFILE%\Desktop
```

**Mac:**
```
cd ~/Desktop
```

Ничего не ответит — так и должно быть.

### 1.4. Проверить, что Java видна

Введите и нажмите Enter:

```
keytool
```

**Если появился длинный текст с описанием команд** — всё хорошо,
переходите дальше.

**Если написано «не является внутренней или внешней командой»** —
Java не установилась или не включили галочку JAVA_HOME. Переустановите
Java, включив её. После установки **закройте чёрное окно и откройте
заново** — иначе оно не увидит изменений.

### 1.5. Создать ключ

Скопируйте эту строку целиком и вставьте в окно
(в Windows вставка — правая кнопка мыши, не Ctrl+V):

```
keytool -genkeypair -v -keystore auron-release.keystore -alias auron -keyalg RSA -keysize 2048 -validity 10000
```

Нажмите Enter. Программа задаст вопросы **по-английски**. Вот что
отвечать на каждый:

| Что спросит | Что делать |
|---|---|
| `Enter keystore password:` | Придумайте пароль и напечатайте. **Букв на экране не появится — это нормально**, так сделано для защиты. Печатайте вслепую и жмите Enter |
| `Re-enter new password:` | Тот же пароль ещё раз, тоже вслепую |
| `What is your first and last name?` | Ваше имя. Или просто `Auron` |
| `What is the name of your organizational unit?` | Просто Enter |
| `What is the name of your organization?` | `Auron` |
| `What is the name of your City or Locality?` | Ваш город, английскими буквами: `Grozny` |
| `What is the name of your State or Province?` | Регион, английскими: `Chechnya` |
| `What is the two-letter country code?` | `RU` |
| `Is CN=... correct?` | Напечатайте `yes` и Enter |

Если в конце спросит `Enter key password for <auron>` — просто нажмите
Enter, это значит «тот же пароль, что и раньше».

### 1.6. Проверить, что получилось

На **Рабочем столе** появился файл `auron-release.keystore`.
Он маленький, около 3 килобайт. Открывать его не нужно и нельзя —
внутри не текст.

**Запишите прямо сейчас, пока не забыли:**

```
Файл:   auron-release.keystore  (Рабочий стол)
Пароль: ..........
Alias:  auron
```

Пароль восстановить невозможно. Забыли — ключ бесполезен.

## Шаг 2. Сохранить в трёх местах

Это единственная вещь в проекте, которую **нельзя восстановить**.
Потеряете — обновления перестанут вставать поверх, и людям придётся
удалять приложение вместе со всеми данными.

Храните файл **и пароль** в трёх местах, одно из них — не дома:
1. компьютер;
2. флешка или второй компьютер;
3. зашифрованный архив в облаке либо у родственника.

## Шаг 3. Превратить файл в текст

GitHub принимает только текст, а ключ — файл. Переведём его в текст.

В том же чёрном окне (вы всё ещё на Рабочем столе) введите:

**Windows:**
```
certutil -encode auron-release.keystore key.txt
```

**Mac:**
```
base64 -i auron-release.keystore -o key.txt
```

На Рабочем столе появится файл **`key.txt`**. Откройте его двойным
щелчком — внутри длинная строка из букв и цифр.

> **Только для Windows.** В файле сверху и снизу будут строки
> `-----BEGIN CERTIFICATE-----` и `-----END CERTIFICATE-----`.
> **Удалите обе эти строки**, оставьте только буквы и цифры между
> ними. Сохраните файл (Ctrl+S).

## Шаг 4. Положить в GitHub

Здесь всё мышкой, командная строка больше не нужна.

1. Откройте ваш репозиторий на **github.com**
2. Сверху вкладка **Settings** (шестерёнка)
3. Слева в списке — **Secrets and variables**, под ним **Actions**
4. Зелёная кнопка справа — **New repository secret**

Создайте **четыре** секрета. Для каждого: вводите имя, вставляете
значение, жмёте **Add secret**. Потом снова New repository secret.

| Name (имя) | Secret (значение) |
|---|---|
| `KEYSTORE_BASE64` | всё содержимое `key.txt` (выделить Ctrl+A, копировать) |
| `KEYSTORE_PASSWORD` | ваш пароль от ключа |
| `KEY_ALIAS` | `auron` |
| `KEY_PASSWORD` | тот же пароль |

Имена — **точно как в таблице**, большими буквами и с подчёркиваниями.
Ошибка в имени = сборка не найдёт ключ.

После сохранения GitHub **больше никогда не покажет** эти значения —
ни мне, ни вам. Их можно только заменить. Так и задумано.

## Шаг 5. Сказать мне

Напишите «ключ положил» — я включу в файле сборки блок подписи
(он уже написан, просто закомментирован) и уберу отладочную версию.
Ключ при этом останется невидимым: сборка берёт его из хранилища сама.

---

## Что будет дальше

С этого момента каждая сборка подписывается вашим постоянным ключом.
Обновления встают поверх старой версии, **данные людей сохраняются**.

Отладочные версии, которые вы соберёте до этого, обновить будет
нельзя — их придётся удалить и поставить подписанную заново. Поэтому
до раздачи людям стоит сделать ключ сразу.

---

## Если ключ всё-таки потерян

Честно: восстановить нельзя, это устройство защиты, а не недоработка.
Что останется:
1. создать новый ключ;
2. выпустить приложение как новое (другое имя пакета);
3. попросить людей сделать резервную копию **до** удаления старого,
   поставить новое и загрузить копию.

Данные сохранятся, но каждому человеку придётся проделать это руками.
Именно поэтому три места хранения — не перестраховка.
