## 3. `api.js` — слой данных (источник всех данных)

Один слой между приложением и backend (PostgREST + RPC поверх PostgreSQL). Правила:
**суммы всегда в копейках** (bigint), деление на 100 только при показе; `client_uuid` на каждой
транзакции — защита от двойного нажатия; мягкое удаление через `deleted_at`; финансовый реестр
(проводки) неизменяем — ошибка правится сторно.

Функции группируются по доменам схемы (05-ARCHITECTURE). `✅` = есть, дорабатываем; `➕` = добавить.

### 3.1 Низкоуровневое (есть)
`_base, _key, _headers, _req, _rpc, _q` — запросы; `kopecks, rub, rubInt` — конвертация сумм;
`uuid` — генерация client_uuid; `periodRange` — границы периода (сегодня/неделя/месяц/год/свой).

### 3.2 Организации и доступ (Домены 1–2)
- `getOrgs()` ✅ — список магазинов пользователя (мультимагазин).
- `createOrg(name)` ✅ + `_ensureDefaultAccounts`, `_ensureDefaultCategories` ✅ — создание магазина с дефолтами.
- ➕ `getMembers(orgId)` / `inviteMember(phone, roleId)` / `updateMember` / `suspendMember` — управление доступом.
- ➕ `getRoles(orgId)` / `saveRole(name, permissionKeys[])` — роли как наборы разрешений.
- ➕ `getMyPermissions(orgId)` — какие права у текущего пользователя (для скрытия экранов/кнопок).
- ➕ `acceptInvitation(token)` — принять приглашение по ссылке.

### 3.3 Счета, категории, транзакции (Домены 4–6)
- `getAccounts / saveAccount / deleteAccount / adjustBalance` ✅ — счета (касса/банк/резерв/карта).
- `getCategories / saveCategory / deleteCategory` ✅ — статьи доходов/расходов.
- `saveTransaction / saveTransfer / deleteTransaction` ✅ — операции (под капотом создают проводки double-entry).
- `getTransactions / searchTransactions` ✅ — история и поиск.
- `_updateAccountBalance`, `_fmtTx` ✅ — внутреннее.
- ➕ `restoreTransaction(id)` — вернуть из корзины (30 дней).
- ➕ `getCategoryRules / saveCategoryRule` — автокатегоризация по ключевым словам.
- ➕ `getBudgets / saveBudget` + `getBudgetStatus(period)` — бюджеты ядра (план/факт по категориям).

### 3.4 Касса — модуль Розница (Домен 7)
- `saveShift / getShifts / cancelShift`, `_fmtShift` ✅ — Z-отчёт; отмена делает сторно и снимает блокировки.
- ➕ `getShiftWithdrawals(shiftId)` / `saveWithdrawal` — выплаты с кассы (поставщик/зарплата/иман/инкассация/прочее).
- ➕ `getOpenShifts()` — для бейджа «смена не закрыта» и чеклиста дня.
- Логика расхождения считается на сервере (RPC) и хранится в `shifts.discrepancy_kopecks`.

### 3.5 Поставщики и заказы (Домен 7)
- `getCounterparties / saveCounterparty` ✅ — справочник поставщиков (+ `custom_fields`).
- `getDebts / getDebtEntries / saveDebtEntry / deleteDebtEntry` ✅ — долги (операции типа initial/purchase/payment/return/adjustment).
- ➕ `getSupplierContacts / saveContact` — несколько контактов на поставщика (WhatsApp).
- ➕ `getScheduledPayments(date)` — запланированные выплаты на дату (вкладка «Выплаты»).
- ➕ `reschedulePayment(id, mode, newDate, newAmount)` — перенести/увеличить/освободить.
- ➕ `getOrders / saveOrder / receiveOrder(id, factAmount, payNow) / cancelOrder` — заказы (planned/received/cancelled), приход создаёт долг.
- ➕ `getSupplierReliability(id)` — надёжность: точность сумм, пунктуальность, явка на выплаты.

### 3.6 Персонал (Домен 9)
- `getEmployees / saveEmployee / deleteEmployee` ✅ — сотрудники; «увольнение» = статус, история остаётся.
- ➕ `getTimesheet(date) / saveTimesheet(employeeId, date, status, coef) / confirmDay(date)` — табель.
- ➕ `getContracts / saveContract` — история ставок (fixed/hourly/percent).
- ➕ `calcSalary(employeeId, period)` — расчёт: ставка × отработано − авансы; собирает авансы сам.
- ➕ `paySalary(calcId, amount)` — выплата, пишет транзакцию и историю.

### 3.7 Финансы: накопления, цели, календарь (Домены 6, аналитика)
- ➕ `getReserveItems(month)` — статьи накоплений (план/отложено/осталось/в день).
- ➕ `topUpReserve(itemId, amount)` — пополнить (виртуальный резерв или физический перевод — по `savings_method`).
- ➕ `saveReserveItems(month, items[])` — настроить статьи на месяц.
- ➕ `getGoals / saveGoal / topUpGoal / closeGoal` — цели владельца (выручка/расходы/прибыль/долг/накопления).
- ➕ `getMoneyCalendar(month)` — календарь денег: по дням приток vs выплаты, прогнозный остаток.
- `getAnalytics / getCashierAnalytics / getHeatmap` ✅ — аналитика выручка/расходы/кассиры/рентабельность.
- ➕ `getProfitability(period)` — рентабельность по магазину и товарам.

### 3.8 Отчёты и закрытие месяца (Домены 4, 10)
- ➕ `buildDailyReport(date)` — 8 блоков дневного отчёта (см. раздел 8.4 и сценарий 7а).
- ➕ `buildMonthlyReport(month)` — доходы/расходы по категориям/прибыль/долг/кассовая книга.

## 5. `state.js` — память приложения (создать)

Единый объект состояния + подписка на изменения (минимальный «стор», без фреймворка).

- Хранит: `user`, `currentOrgId`, `role`, `permissions[]`, `style` (градиент/классика), `theme`,
  `density`, `uiLevel` (простой/стандартный/расширенный), активные модули магазина, кэш справочников
  (счета, категории, поставщики, сотрудники), черновик формы, статус сети (🟢🟡🔴).
- API: `get(key)`, `set(key, value)`, `subscribe(key, fn)`, `select(fn)`.
- **Оптимистичный UI**: модуль меняет state локально мгновенно → `api` пишет на сервер → при ошибке
  откат + toast. (Паттерн из 04-DESIGN-SYSTEM.)
- **Realtime**: подписка на изменения магазина по WebSocket → обновляет state → перерисовка
  (3+ человека в одном магазине видят изменения без перезагрузки).
- **Черновик**: незавершённая форма автосохраняется каждые 30 сек, красная точка на FAB.

## 6. Фундамент: `bus.js`, `router.js`, `ui.js`, `i18n.js`

### 6.1 `bus.js` — шина событий (создать)
Все модули общаются через события, не напрямую (принцип 2 из 05-ARCHITECTURE).
- API: `emit(event, payload)`, `on(event, handler)`, `off(...)`.
- Ключевые события: `shift.closed`, `debt.added`, `payment.made`, `order.received`,
  `salary.paid`, `transaction.created`, `month.closed`.
- Слушатели: Аудит, Уведомления, Пульс, Календарь денег, Надёжность поставщика, Вебхуки.
- Новая реакция = новый `on(...)`, старый код не меняется.

### 6.2 `router.js` — навигация (создать)
- SPA-переключение вкладок без перезагрузки; нижняя панель на телефоне (макс 5 вкладок, 6-я → «Ещё»),
  боковая на планшете/ПК.
- Набор вкладок зависит от тарифа/модулей: Личный → Главная·Операции·Аналитика·Настройки;
  Ритейл → Главная·Касса·Поставщики·Финансы·Ещё(Операции·Персонал·Товары·Настройки).
- Перед показом экрана проверяет права (`state.permissions`) — нет права → экран/кнопка скрыты.
- Глубокие ссылки (`auron://suppliers/ivanov`), Pull-to-refresh, Pull-to-search.

### 6.3 `ui.js` — общие кирпичики (создать)
Реализуют дизайн-систему (04), переиспользуются всеми модулями:
`bottomSheet(content)`, `toast(msg, {undo})`, `numpad({calc:true})`, `skeleton()`,
`progressBar(value, mode)` (цвет по смыслу: накопления больше=лучше, бюджет больше=хуже),
`txRow(tx)`, `categoryIcon(cat)`, `emptyState(icon, text, action)`, `confirmDanger(text, count)`,
`amountInput()` (цифровая клавиатура автоматически), `haptic(type)`.
Правила: только Bottom Sheet (модалок нет), суммы по правому краю, копейки только если ≠ 00.

### 6.4 `i18n.js` + `ru.json` (создать)
Ни одной строки текста в коде — всё через `t('key')`. `ru.json` — словарь. Добавить язык потом =
перевести один файл. Узбекский/киргизский/казахский — кандидаты v2.

## 7. Модули-экраны (`js/modules/`)

Каждый модуль: функция `render(container)` рисует экран, набор обработчиков действий, подписки на
события шины. Ниже — назначение, состав и логика по каждому (детали в 02-FLOWS и 03-SCREENS).

### 7.1 `home.js` — Главная
**Показывает:** Финансовый пульс 🟢🟡🔴 (тап → объяснение), название магазина, [🔔][💬ИИ][⚙️];
чеклист дня (Z-отчёт/выплаты/табель/отчёт); баланс — Наличка / Выручка сегодня / **Свободно**;
4 быстрых действия (Z-отчёт/Выплата/Заказ/Отчёт); умные карточки (смена не закрыта, выплаты сегодня,
ожидаемые заказы, накопления с прогрессом).
**Логика:** карточки появляются только если релевантны; адаптивная Главная — частые разделы вверх,
неиспользуемые 30+ дней вниз; контекстная подсказка только после 20+ повторений.
**Роли:** Бухгалтер — полная; Администратор — без сумм кассы; Владелец — только просмотр; Сотрудник
зала — только заказы/поставки. Отдельный экран **«Все магазины»** для владельца сети.
**Функции:** `render`, `renderPulse`, `renderChecklist`, `renderBalance`, `renderQuickActions`,
`renderSmartCards`, `openZReport`, `openPayment`, `openOrder`, `openReport`.

### 7.2 `kassa.js` — Касса (Z-отчёт)
**Вкладки:** Новая смена / История.
**Форма смены:** дата, смена (день/ночь), кассир; по Z-отчёту (наличка/карта/СБП); фактическая
наличка; выплаты с кассы (добавить/удалить); внизу — **Расхождение** (формула 8.1) с цветом.
**Логика:** карта и СБП зачисляются на банковский счёт, не на наличку; иман — отдельный тип выплаты,
входит в формулу один раз; ночная смена привязывается к дате начала или конца (настройка); дубль
даты+смены открывает существующий с [Редактировать]; исправление пересчитывает балансы + аудит;
дата в будущем заблокирована. После закрытия — событие `shift.closed`.
**Роли:** только Бухгалтер (полный), Владелец — просмотр.
**Функции:** `render`, `renderNewShift`, `renderHistory`, `addWithdrawal`, `calcDiscrepancy`,
`saveShift`, `openShift`, `editShift`.

### 7.3 `suppliers.js` — Поставщики
**Вкладки:** Выплаты / Поставщики / Заказы.
- **Выплаты:** сгруппированы Сегодня/Завтра/Позже; по тапу — [Оплатить] (наличка + погашение долга +
  новый долг) / [Перенести] (завтра / завтра+сумма / дата / освободить) / [Не пришёл] / [Отменить].
  Карточка ИИ-порядка выплат если денег меньше плана (Пакет ИИ).
- **Поставщики:** общий долг в шапке, поиск, список с долгами; карточка — контакты, WhatsApp,
  текущий долг, статистика, история, надёжность %; [Выплатить][Накладная][Возврат].
- **Заказы:** активные (Ожидается/В пути/Сегодня) + история; по тапу — [Товар пришёл] (факт. сумма +
  оплата сразу/в долг) / [Перенести] / [Отменить]; [+ Новый заказ].
**Логика (формула 8.2):** новый долг = старый + взяли − погасили; переплата → отдельной строкой
с предупреждением; оплата > свободного → предупреждение, не блокирует; удаление поставщика с историей —
только архив; 80+ → алфавитная группировка. События: `debt.added`, `payment.made`, `order.received`.
**Роли:** Бухгалтер — полный; Администратор — заказы + запись выплат (без проведения оплат); Владелец —
просмотр; Сотрудник зала — поставки без сумм.

### 7.4 `staff.js` — Персонал
**Вкладки:** Табель / Сотрудники / Зарплата.
- **Табель:** навигация по дням, статус по каждому (Вышел/Полдня/Выходной/Больничный/Прогул/Отпуск),
  коэффициент (скрыт, появляется при нестандартной оплате), [Подтвердить день].
- **Сотрудники:** активные (имя/должность/ставка) + свёрнутые уволенные; карточка — график, авансы,
  история выплат, [Редактировать][Уволить].
- **Зарплата:** период, по каждому расчёт (дни × ставка − авансы = итого), [Выплатить] (сумма
  редактируема), блок незакрытых дней.
**Логика (формула 8.3):** авансы = транзакции категории «Аванс» с employee_id, вычитаются автоматически;
авансы > заработка → ₽0 и перенос; увольнение с долгом по ЗП → предупреждение; правка табеля задним
числом разрешена и фиксируется в аудите. Событие `salary.paid`.
**Роли:** Бухгалтер — полный; Администратор — просмотр табеля; Владелец — просмотр.

### 7.5 `finance.js` — Финансы
**Вкладки:** Накопления / Цели / Календарь / Аналитика / Отчёт.
- **Накопления:** по статьям прогресс-бар (отложено/план), «нужно в день», статус ✓/Отстаём;
  [Пополнить][Настроить статьи]. Формула 8.4. Виртуальный резерв vs физический счёт (настройка).
- **Цели:** активные с трендом и прогнозом + закрытые; создание цели (тип/сумма/период/направление);
  «нужно в день чтобы догнать». Ставит владелец.
- **Календарь денег:** сетка на 30 дней, день окрашен 🟢 приход / 🔴 крупные выплаты / 🟡
  неопределённость; тап → детали и прогнозный остаток.
- **Аналитика:** Выручка/Расходы/Кассиры/Рентабельность × период (неделя/месяц/квартал/год); графики
  на `chart.min.js`; ИИ-инсайт (Пакет ИИ).
- **Отчёт:** дневной ([WhatsApp][Telegram][PDF]) и месячный; **закрытие месяца** с чеклистом
  готовности; кассовая книга; правка закрытого периода — через причину + одобрение владельца.
**Роли:** Бухгалтер — полный; Владелец — просмотр + создание целей.

### 7.6 `products.js` — Товары (опционально)
Показывается только в ручном режиме учёта; в режиме 1С — экран импорта.
**Вкладки:** Товары / Приход / Рентабельность.
- **Товары:** каталог, закупка/продажа/наценка %, архив.
- **Приход:** по датам, форма (поставщик/товар/кол-во/сумма/оплата сразу или в долг → растит долг).
  Опционально фиксация продажи.
- **Рентабельность (формула 8.6):** общая и по товарам, сравнение с целевым %.
- **Режим 1С:** [Загрузить отчёт из 1С (Excel)] + история импортов.
**Роли:** Бухгалтер+Администратор — полный; Сотрудник зала — без закупочных цен; Владелец — просмотр.

### 7.7 `transactions.js` — Операции (ядро)
История транзакций ядра (для Личного/ИП и как общий журнал в Рознице): группировка
Сегодня/Вчера/дата + дневные итоги; свайп влево → Редактировать/Удалить; долгое нажатие → Повторить;
быстрый ввод через FAB (тип → сумма → счёт → категория → коммент). Автокатегория по ключевым словам.
**Функции:** `render`, `renderGroups`, `openQuickAdd`, `saveTx`, `repeatTx`, `editTx`, `deleteTx`.

### 7.8 `settings.js` — Настройки
Разделы: Магазин (название/отделы/статьи накоплений/метод накоплений/ночная смена/целевая

Интеграции (WhatsApp/Telegram/1С/Банк/Zapier/API-ключ/Webhooks/email накладных); Подписка; Несколько

## 8. Формулы (источник правды)

Все суммы в копейках; проценты — при показе. Эти формулы реализуются в `api.js`/RPC, не дублируются
в модулях.

**8.1 Расхождение кассы** (`shifts.discrepancy_kopecks`)
```
Расхождение = (Фактическая наличка + Выплаты с кассы) − Z-отчёт
< 0 → недостача (🔴 --expense) · > 0 → излишек (🟡 --transfer) · = 0 → идеально (✓ --income)
```

**8.2 Долг поставщику** (накопительно по `debt_entries`)
```
Новый долг = Старый долг + Взяли в долг (purchase) − Погасили (payment) ± корректировки
```

**8.3 Зарплата к выплате** (`salary_calculations`)
```
К выплате = Ставка × Отработано (дней/часов × коэффициент) − Авансы за период
авансы < 0 итога → к выплате ₽0, остаток переносится
```

**8.4 Ежедневное откладывание (накопления)**
```
В день = (Плановая сумма статьи − Уже отложено) / Дней до конца месяца
статус: успеваем (✓) если темп достаточен, иначе «Отстаём»
```

**8.5 Финансовый пульс** (`pulse_snapshots`, веса из 05-ARCHITECTURE)
```
Score = 0.30·(выручка vs средняя) + 0.30·(долги vs лимит)
      + 0.20·(накопления vs план) + 0.20·(расхождения за неделю)
🟢 green · 🟡 yellow · 🔴 red — по порогам. Пересчёт при каждом закрытии смены.
```

**8.6 Рентабельность**
```
Рентабельность = (Выручка − Себестоимость) / Выручка × 100%
себестоимость — из импорта 1С или из карточек товара (ручной режим)
сравнивается с целевым % магазина (settings.target_margin_percent)
```

**8.7 Свободно / Доступно** (термины из 04, не смешивать)
```
Свободно (Розница) = Наличка в кассе − плановые выплаты − резервы накоплений
Доступно (Ядро)    = Баланс счёта − сумма бюджетов − цели
```

**8.8 Календарь денег (прогнозный остаток дня)**
```
Остаток(день) = Остаток(день−1) + плановый приток(день) − плановые выплаты(день)
🟢 приток > выплат · 🔴 крупные выплаты · 🟡 выплаты близко к остатку
```

## 10. Правила, действующие везде

- **Деньги — в копейках.** Float в коде запрещён, деление на 100 только при показе.
- **Финансовый реестр неизменяем.** Правка = сторно + новая проводка. Закрытый месяц — `locked`.
- **Мягкое удаление.** Корзина 30 дней, восстановление пересчитывает балансы.
- **Аудит на каждое изменение.** Кто, когда, было→стало — навсегда.
- **Тексты — только через словарь** (`i18n`). Ни одной строки в коде.
- **Дизайн-система — через `ui.js`.** Только Bottom Sheet, FAB, цвета по смыслу, два стиля (Градиент/Классика).
- **Оптимистичный UI + офлайн-просмотр.** Ввод без сети заблокирован с понятным сообщением.
- **Права на экран и кнопку** проверяются через `state.permissions` (движок прав, не жёсткие роли).
- **Шина событий.** Новая реакция = новый слушатель, старый код не трогаем.
- **Тихий старт.** Первые 14 дней — тишина, только критические ошибки.
- **`sw.js` версия** бампается при каждом изменении фронта (`auron-vNN`).
- **Не добавляем фичи без утверждённого документа** (правило CLAUDE.md).
```
