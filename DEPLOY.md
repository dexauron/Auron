# Как Auron попадает в интернет

Две части, разные способы.

## Приложение — GitHub Pages, само

Фронтенд собирается и публикуется автоматически при пуше.
Ничего запускать вручную не нужно.

**Адрес:** https://dexauron.github.io/Auron/

**Как это устроено:** `.github/workflows/deploy.yml` собирает сайт из трёх
источников, каждый из своей ветки:

| Часть | Ветка | Папка |
|---|---|---|
| Приложение Auron | `claude/optimistic-einstein-Afzmv` | `app/` |
| Каталог товаров | `claude/store-product-catalog-60wer4` | `catalog/` |
| Страница сканера | `claude/cool-archimedes-qv458l` | `app/scan.html` |

Пуш в одну ветку не задевает остальные части.
Меняешь workflow — синхронизируй его во все ветки, иначе развалится сборка.

**После изменения фронта обязательно** подними версию кэша в `app/sw.js`
(`auron-vNN`), иначе у пользователей останется старая версия из кэша.

## База и вход — self-hosted Supabase

Работает на VPS Timeweb Cloud (Москва), развёрнут и настроен.

| Что | Где |
|---|---|
| Сервер | `201.51.6.170` |
| Панель управления | `http://201.51.6.170:8000` |
| Стек | PostgreSQL, Auth, PostgREST, Realtime, Storage |

Порт 5432 закрыт файрволом — postgres доступен только изнутри.

Ключи для приложения лежат в `app/js/config.js` (`SUPABASE_URL`,
`SUPABASE_ANON_KEY`).

### Миграции

Схема базы — в `infra/migrations/`, применяются по порядку номеров
через SQL-редактор в панели Supabase.

```
001_initial_schema.sql   таблицы, RLS, изоляция по организациям
002_functions.sql        сводка балансов
003_demo_data.sql        демо-данные
004_fixes.sql            правки функций
005_retail_domains.sql   касса, заказы, накопления, персонал
```

Каждая миграция написана так, чтобы повторный запуск не ломал данные
(`IF NOT EXISTS`, перехват `duplicate_object`).

### Что нужно донастроить

**SMS-провайдер.** Вход по телефону (`03-SCREENS.md`, Экран 0а) написан
в `app/js/auth.js`, но не заработает, пока в Supabase Auth не подключён
провайдер SMS — SMS.ru, SMSC или другой. До тех пор рабочий вход —
email и пароль.
