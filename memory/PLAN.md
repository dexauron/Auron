# PLAN — план написания кода Auron v1

> План, а не код. Основан на `docs/05-ARCHITECTURE.md` (утверждён) и структуре из `CLAUDE.md`.
> Код пишется в ветке приложения `claude/optimistic-einstein-Afzmv`, не в ветке скилов.

## Порядок (снизу вверх: сначала фундамент, потом экраны)

### Фаза 0 — Фундамент (закладывается с первого дня, потом не добавить)
- **Шина событий** (`state.js`/отдельный модуль) — публикация/подписка. См. `auron-modules`.
- **Feature flags** — чтение `feature_flags` + `user_feature_flags`.
- **Движок прав** — проверка по permission-ключу, не по имени роли. См. `auron-rls-roles`.
- **Трекинг** — запись `analytics_events` на ключевых действиях.

### Фаза 1 — Слой данных `app/js/api.js` (ПЕРВЫЙ шаг по CLAUDE.md)
- Привести под утверждённую схему (76 таблиц). Использовать существующий `_q/_rpc`.
- Правила: копейки bigint, ISO-даты, UUID, `client_uuid` на записи, опора на RLS.
- См. скилы `auron-supabase-api`, `auron-money-format`, `auron-double-entry`.

### Фаза 2 — Авторизация `app/js/auth.js`
- Перенести JWT+refresh на self-hosted, добавить мультимагазинность (`org_members`).
- PIN (хэш), 5 попыток → блок + email-reset, автоблокировка. См. `auron-security-antipatterns`.

### Фаза 3 — Каркас: `state.js` + `router.js` + `index.html`
- Глобальный стейт, SPA-навигация, HTML-каркас по дизайн-системе (`docs/04-DESIGN-SYSTEM.md`).
- Service Worker: офлайн=просмотр, `auron-vNN`. См. `auron-offline-sync`, `auron-pwa-deploy`.

### Фаза 4 — Модули (каждый = новый файл в `js/modules/` + регистрация в `router.js`)
1. `home.js` — Главная (пульс, балансы, виджеты)
2. `kassa.js` — Касса / Z-отчёт (двойная запись, отмена смены)
3. `journal.js` — Журнал операций
4. `analytics.js` — Аналитика
5. `settings.js` — Настройки (модули, роли, интеграции, бэкапы)

### Фаза 5 — Интеграции и бэкапы (по приоритету)
- Web Share сразу; Telegram Bot/WhatsApp — как апгрейд. См. `auron-integrations`.
- Автобэкап в облако владельца (шифрование до отправки). См. `auron-cloud-backup`.

## Незыблемые правила на всех фазах
- Деньги в копейках; реестр неизменяем (только сторно); изоляция через RLS.
- Офлайн=просмотр; `client_uuid`; бамп `auron-vNN` при изменении фронта.
- Auron и `catalog/` — раздельно. Не хардкодить то, что должно быть в конфиге.
- Перед необратимым — подтверждение владельца.

- По ходу — решения там, где документы оставляют выбор (отмечать в `docs/DECISIONS.md`).
