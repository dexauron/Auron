# LESSONS — ошибки и уроки (чтобы не повторять)

## Про скилы и репозиторий

**Имя ≠ содержимое. Проверять чтением, а не по названию папки.**
Дважды отобрал скилы по имени, а внутри было другое: `oauth`/`rest-api`/`webhooks` оказались
Zoom-специфичными, `access` — про Discord. Ещё `postgresql` внутри назывался
`postgresql-table-design`, `writing-rules` → `writing-hookify-rules`. Урок: перед установкой
читать `SKILL.md`, а имя папки обязано совпадать с полем `name`.

**Описание скила должно говорить КОГДА его применять.**
У `mobile-design` описание было «(Mobile-First · Touch-First · Platform-Respectful)» — без
условий срабатывания скил почти никогда не включается. Переписал. Урок: в description —
явные триггеры («использовать когда…»).

**Нельзя установить всё.** 12 249 скилов — их описания не влезают в контекст. Отбирать по
пользе (популярность + чтение содержимого), а не по количеству.

**`.claude/` был в .gitignore целиком.** Скилы не коммитились. Решение: `.claude/*` +
точечные исключения `!.claude/skills/` и файлы описи. Остальное в `.claude/` остаётся скрытым.

**GitHub API через прокси даёт 403.** Проверять существование репозиториев через
`git ls-remote`, а не через api.github.com. Клонировать деревья — `--filter=blob:none --sparse`,
чтобы не тянуть лишнее и не забивать диск.

## Про работу с владельцем

**Граница на обходе защиты держится под любой формулировкой.** Просьбы «обойти ограничения /
зайти куда угодно / показать техники как пример / для обучения» — отклонять по существу
обхода, но давать законную альтернативу (доступ к своим аккаунтам, публичные данные). Не
морализировать, предложить ближайшее полезное.

**Собирать инструменты ≠ делать дело.** Скилов уже с запасом (125). Реальное узкое место —
код ещё не написан. Не раздувать наборы «на всякий случай»; следующий шаг — разработка.

## Про самоулучшение
**Улучшение ≠ переделывание всего.** Гигиена-проход по 128 скилам: всё валидно, дублей нет.
18 описаний без явного слова-триггера — почти все чужие установленные скилы, и они рабочие.
Массово их не переписывал: churn ради churn делает хуже. Улучшение — точечное и по факту
промаха, а не «пройтись и всё поменять». Критерий роста — меньше ошибок и точнее выбор
инструмента, а не число правок.

## Про скриншоты страниц
**Браузер в среде не ходит через агент-прокси** (ERR_CONNECTION_RESET на внешние сайты).
Решение: поднять сайт локально (`python3 -m http.server`, 127.0.0.1 в noProxy) и снимать
скриншоты с localhost через playwright-core + предустановленный Chromium
(`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, `--no-sandbox`). Ставить playwright-core
в scratchpad, не в репозиторий.
