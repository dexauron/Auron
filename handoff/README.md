## Что это за продукт

Приложение для учёта денег в розничном магазине. Владелец — не
программист. Задача: закрыть день за 2–3 минуты и всегда знать три вещи:
сколько денег, сколько должны поставщикам, сколько заработали.

Действующий магазин: продуктовый, ~16 500 позиций товара, две смены
(день/ночь), поставщики приезжают в течение дня, товар часто берут в долг.
Учёт в 1С ведётся параллельно — приложение его **не заменяет**, а отвечает
на денежные вопросы быстро.

## Из чего состоит

```
webapp/Code.gs      серверная часть  (~9 300 строк, Google Apps Script)
webapp/Index.html   всё приложение   (~13 800 строк: вёрстка + стили + логика)
webapp/tests/       41 файл проверок (обычный Node.js, без фреймворков)
docs/               вся история решений и требования
.claude/skills/     рабочие процедуры (проверка перед выкладкой, снимки экрана)
```

Фронт и бэк — по одному файлу каждый. Так сложилось из-за платформы
(Google Apps Script не даёт нормальной сборки), и это **первое, что стоит
разделить** при переносе.

## С чего начать новому разработчику

1. `01-ARCHITECTURE.md` — понять устройство за 15 минут.
2. `02-DATA-MODEL.md` — понять данные. Это главное: логика следует из них.
3. `06-KNOWN-ISSUES.md` — узнать, где мины.
4. Запустить проверки: `bash .claude/skills/preflight/scripts/preflight.sh`.
   Они не требуют ни Google, ни интернета — только Node.js.
5. Посмотреть экраны без сервера:
   ```
   node .claude/skills/look/scripts/gas.js webapp/Index.html /tmp/x.html webapp/tests/fixtures/ui-stub.json
   node .claude/skills/look/scripts/shot.js /tmp/x.html
   ```

## Чего в приложении принципиально нет

- Нет кассового оборудования и фискализации — выручка вводится по Z-отчёту.
- Нет складского учёта по позициям — только деньги и итоги по товарам из 1С.
- Нет бухгалтерии по документам. Это осознанно: «лёгкий» учёт за минуты.
