# Перенос базы каталога на другой сервер

Переносим **только базу** (товары, фото, цены, продажи, аккаунты). Сама страница
каталога остаётся на GitHub Pages — я просто пропишу новый адрес базы в конце.
**Данные не теряются.** Старый сервер держим включённым, пока не проверим новый.

---

## Важно: как клиенты попадут на новый сервер

Клиенты открывают каталог из интернета. Значит, новый сервер должен быть
**доступен из интернета по HTTPS**. Возможны три случая:

- **Обычный VPS с публичным IP** (как сейчас Timeweb) — проще всего: скрипт сам
  поднимает HTTPS-адрес вида `IP.sslip.io`.
- **Домашний ПК за роутером** (адрес вида `192.168.x.x`) — напрямую из интернета
  недоступен. Нужен **туннель** (например, бесплатный Cloudflare Tunnel: HTTPS,
  без настройки роутера) или **проброс портов** на роутере. Под этот случай я дам
  отдельные точные команды — напиши, что сервер домашний.
- **Только для магазина (локальная сеть)** — если каталогом пользуются лишь
  сотрудники внутри магазина. Тогда доступ из интернета не нужен, но и клиенты со
  своих телефонов из дома зайти не смогут.

Скажи, какой у тебя случай — от этого зависит шаг 1.

---

## Шаг 1. Поднять Supabase на новом сервере

**Публичный VPS (чистый Ubuntu 22.04/24.04):** запусти от root установщик
`server-install.sh` — он поставит Docker, Supabase и HTTPS, и напечатает
**адрес** и **ключи**.

**Домашний ПК / за роутером:** ставим Supabase так же, но HTTPS делаем через
туннель (я дам команды под Cloudflare Tunnel). Итог тот же — публичный адрес + ключи.

Сохрани из вывода: `URL`, `ANON_KEY`, `SERVICE_ROLE_KEY`, пароль Studio.
(Секретные ключи и пароли — НЕ присылай в чат; нужен только публичный `ANON_KEY`.)

## Шаг 2. Создать таблицы

В Studio нового сервера → **SQL Editor** → вставь весь `ОБНОВИТЬ-БАЗУ-ПОЛНОСТЬЮ.sql`
→ **Run**. Появятся все таблицы и функции (пустые).

## Шаг 3. Выгрузить данные со старого сервера

На **старом** сервере от root:
```bash
bash migrate-export.sh
```
Получится файл `/root/catalog-migration.tgz`. Скачай его (или сразу скопируй на
новый сервер):
```bash
scp root@СТАРЫЙ-IP:/root/catalog-migration.tgz .
scp catalog-migration.tgz root@НОВЫЙ-СЕРВЕР:/root/
```

## Шаг 4. Загрузить данные на новый сервер

На **новом** сервере от root (архив уже лежит в `/root/`):
```bash
bash migrate-import.sh
```
Скрипт перенесёт товары, цены, продажи, поставщиков и фотографии и покажет,
сколько всего загрузилось.

## Шаг 5. Пересоздать аккаунты

Studio нового сервера → **Authentication → Users → Add user** — создай три
аккаунта (Auto Confirm у каждого):
- `dexauron@gmail.com` — твой, админ;
- `manager@waymarket.ru` — аналитик/зал;
- `staff@waymarket.ru` — общий для сотрудников (пароль магазина).

Роли уже перенесены (таблица `catalog_roles`) — нужны только сами аккаунты.

## Шаг 6. Прописать новый адрес в приложение

Пришли мне в чат **две строки** (публичные, не секретные):
```
АДРЕС : https://…            (новый URL базы)
ANON  : eyJ…                 (публичный anon-ключ)
```
Я обновлю `catalog/js/config.js`, задеплою — и каталог начнёт работать с нового
сервера.

## Шаг 7. Проверить и выключить старый

Открой каталог, войди, проверь: товары, фото, вход сотрудника, «Ходовые», цены.
Всё в порядке — старый сервер можно выключать. Что-то не так — пиши, разберёмся;
старый сервер до этого не трогаем (это наша страховка).

---

## Если на шаге импорта фото «не легли»

Ничего страшного: сами товары и данные на месте. Метаданные фото могут не перенестись
между разными версиями Supabase. Тогда фото известных брендов заново подтянет
автопоиск в приложении (владелец входит → фото ищутся в фоне), а остальные — как
обычно. Напиши мне — подскажу точечно.
