# Передача Claude — Way Market 0.18

## Задача пользователя

Каждый внутренний сотрудник оформляет возвраты поставщику и списания с количеством, кодами, статьёй и причиной, выгружает Excel для ручной загрузки в 1С. В будущем тот же документ передаётся адаптером. Покупательские возвраты сюда не входят.

## Что реализовано

См. RELEASE-0.18.md и docs/GOODS-DOCUMENTS.md. Документы и справочник статей используют события goods.document / goods.articles; повторы — goods.request. Account command объединяет проверку роли, запись и аудит в существующей SQLite-транзакции. Версия — sequence события документа. Автор и снимки товаров берутся с сервера. Финансовые/складские регистры и worksheet.mjs не менялись.

Записи повторов намеренно не добавлены в workspace_requests: существующая проверка резервного архива допускает там только прежние результаты id/version с определёнными связями. Полные результаты новой команды хранятся в событиях, как и новый процесс. Проверка восстановления и повтора после восстановления прошла.

XLSX-шаблон создан Artifact Tool, runtime заполняет его без внешних npm-зависимостей. goods-export.mjs читает локальный шаблон, заменяет sheetData и собирает ZIP со стандартным CRC32. Пользовательские строки — inlineStr, формулы не исполняются, коды остаются текстом. Количество проверяется как десятичная строка/целые тысячные; в Excel пишется числом. Максимум 50 строк ограничивает формат и нагрузку.

## API

GET /api/unified/goods — состояние, статьи и последние 200 доступных документов.
GET /api/unified/goods/products?q=... — поиск для оформления.
POST /api/unified/goods/save — черновик с requestId и expectedVersion.
POST /api/unified/goods/transition — submit / approve / reject / cancel.
POST /api/unified/goods/articles — справочник управляющего с версией.
GET /api/unified/goods/documents/:id — документ.
GET /api/unified/goods/documents/:id/history — история.
GET /api/unified/goods/documents/:id/export?version=... — XLSX подтверждённой версии.
GET /api/unified/goods/documents/:id/contract?version=... — JSON для будущего адаптера.

Публичного endpoint без авторизации нет. POST использует существующую CSRF-границу. GET выгрузки регистрирует только запрос экспорта; успешная загрузка файла пользователем или его импорт в 1С не заявляются.

## Независимо проверить

1. Права внутренних ролей и запрет представителю, чужие ID документов, роли после отзыва сеанса.
2. Повтор команды и конкурентные сохранения одной версии. Подмена requestId, автора, снимков и внешних ID.
3. Границы количества/размера, управляющие символы, пустые значения, DTD в старом импорте, формулы и XML-экранирование в XLSX.
4. Восстановление полного архива, включая goods.request и историю, без потери старых финансовых/кассовых данных.
5. Сохранность более свежих изменений вашего репозитория. Сравнить перед слиянием; тесты запускать на копии.
