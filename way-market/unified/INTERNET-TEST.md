# Way Market · бесплатный интернет-тест 0.16

## Что требуется

Windows-сервер с Node.js 24 (у пользователя проверен 24.22.0), установленный официальный cloudflared, постоянно работающий интернет. На клиентских ПК/телефонах нужен браузер. Публичный IP, проброс портов и VPS для этого теста не требуются.

Это отдельный тест, не промышленное размещение. Используйте вымышленные аккаунты и документы. База хранится на вашем компьютере, но сетевой трафик проходит через Cloudflare. Доступность из сетей России пока не проверена.

## Порядок запуска

1. Извлеките весь ZIP в новую папку. Установка cloudflared выполняется отдельно из официального источника. Не запускайте из ZIP.
2. Откройте `start-tunnel-test.cmd`. Он проверит Node.js 24 и доступность cloudflared.
3. Откроется локальный адрес в браузере. На новой тестовой базе создайте владельца с вымышленным именем; код настройки берётся из этого окна сервера. Пароль и код не присылайте в чат.
4. После создания владельца вернитесь в окно запуска и нажмите Enter. Только теперь запускается cloudflared и появляется временный адрес `https://….trycloudflare.com`.
5. Откройте этот адрес на телефоне с мобильным интернетом, отключив Wi-Fi и VPN. Войдите тестовым аккаунтом. Проверьте главную, каталог, смены и выполнение тестовой задачи. Повторите на другом ПК.
6. Оставляйте окно запуска открытым. Ctrl+C останавливает туннель и отдельное тестовое приложение. После перезапуска ссылка может измениться; вход по новой ссылке потребуется заново.

Появление ссылки не доказывает, что Cloudflare уже доступен с телефона. Если открытие не удалось, сообщите текст ошибки; не присылайте окно с кодом владельца или паролями. Если в домашней папке уже есть настройки cloudflared, они не изменяются; возможный конфликт настройки нужно разобрать отдельно.

## Отделение данных

- Обычный Windows-запуск: `%ProgramData%\WayMarket-Unified-Test\workspace.sqlite`.
- Интернет-тест: `%ProgramData%\WayMarket-Quick-Tunnel-Test\workspace.sqlite`.
- На Linux тест использует `~/.way-market-quick-tunnel-test/`.

Старая база, роли, сеансы и настройки не переносятся автоматически. Копировать в этот тест рабочую базу не требуется. Данные отдельного теста сохраняются между его перезапусками. Два процесса для одной и той же базы запускать нельзя.

## Защита шлюза

Оба локальных порта слушают только 127.0.0.1. Внешний адрес принимается только из вывода запущенного cloudflared и закрепляется точно за одним HTTPS-хостом trycloudflare.com. До получения адреса и создания владельца шлюз закрыт. Публичная первичная настройка запрещена.

Шлюз сверяет Host, HTTPS-протокол и Origin, запрещает cross-site запросы и снимает заголовки перенаправления перед внутренним сервером. Сервер приложения сохраняет прежние проверки CSRF, сеансов и ролей. Сессионные и device-cookie снаружи дополнены Secure, сохраняют HttpOnly/SameSite=Strict. API-ответы не кэшируются. Потеря ответа при передаче не объявляется успешной записью.

## Что проверено

189 автоматических тестов: 96 общей системы и шлюза, 87 рабочей области, 6 запуска. Для шлюза проверены отказ до локального владельца/адреса, pinning хоста, чужой Origin/Host/HTTP, публичный bootstrap, роли, CSRF, cookie, вход и отзыв сеанса. Сетевой тест настоящий: локальные HTTP-запросы проходят через шлюз к серверу приложения; облачное соединение Cloudflare здесь не запускалось.

Нужно проверить на Windows пользователя: установку cloudflared, получение временной ссылки, заголовки реального туннеля, загрузку всех модулей и доступ через сети России. Автозапуск службы и стабильный домен этому временному режиму не добавлены.
