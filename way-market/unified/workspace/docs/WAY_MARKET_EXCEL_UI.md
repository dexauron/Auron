# Кассовый лист по пользовательскому Excel — 0.8

## Подтверждённое решение владельца

Основной экран должен повторять колонки, строки заполнения и выдачи информации из его Excel. «Наличка» и «Эквайринг» — два самостоятельных виджета, затем фактическая наличка и отчёт бухгалтера. Настройки изменяют названия, показывают/скрывают строки, добавляют нужные поля и определяют способ расчёта. Ненужные служебные поля не запрашиваются на основном экране. Оформление в духе iOS, минимум визуальных элементов, пояснения по одному «?» на блок.

Исходный Excel и чеки используются как частные источники требований, не изменяются и не публикуются. В публичном коде/тестах только вымышленные имена и суммы.

## Сопоставление

| Место шаблона | Новый лист |
| --- | --- |
| Дата, принимающий, кассир, число чеков/ФД | Верхняя компактная панель |
| Наличка, наличка через эквайринг | Два независимых денежных источника |
| Выплата ТП, выплата ЗП, обед, чеки владельца | Отдельные строки сумм без обязательных получателей |
| Внесение, возвраты, аннулированные чеки | Строки как в шаблоне; аннулирования — количество |
| Карта, QR, Bluetooth, био, нефискальный отчёт, возвраты, аннулирования | Правый виджет, сохранены привычные названия; смысл сравниваемого отчёта пояснён по «?» |
| Фактическая наличка | Независимый ввод бухгалтера, может оставаться неизвестным |
| Общая торговля и итоговые строки | Автоматический отчёт ниже |

«Чеки владельца» требуют выбора смысла в настройках при ненулевой сумме. Выдача денег и товар без оплаты не считаются одним и тем же событием. Поставка товара, долг и фактическая выплата не смешиваются.

## Формулы

По умолчанию денежная основа повторяет инкассацию с включённым внесением: наличные продажи = первая наличка − внесение + наличка через эквайринг. При другой основе внесение уже исключено из первой суммы и повторно не вычитается. Политика возвратов определяется явно, накопительные суммы ФН не вычитаются автоматически.

К передаче = наличные продажи + фактический начальный остаток + прочие поступления + дополнительные внесения − физические выплаты − неоплаченные чеки, включённые в наличную выручку − предыдущие передачи − оставленные наличные. Дополнительные движения изначально не используются и не запрашиваются. Их можно включить в настройках.

Эквайринг = карта + QR + Bluetooth + био − возвраты только при соответствующей политике. Расхождение отчётов = терминал − кассовый безналичный итог. Общая торговля = наличные продажи + кассовый безналичный итог. В исходной формуле общего итога был пропуск второго наличного источника; он исправлен. Используется кассовый безналичный итог, чтобы расхождение терминала не меняло продажи незаметно.

Торговля по факту — только наличная часть, восстановленная из принятой суммы обратным учётом движений. Название уточнено на экране. Разница = принято − к передаче. Плюс/минус описывают расхождение, а не доказывают виновность. Настройки являются заявленной основой расчёта, не согласованием выплаты. Эти суммы не подставляются автоматически в чистую прибыль.

Парсер денежных значений прежний: десятичный текст, до двух знаков копеек, суммы в целых копейках. Промежуточное сложение BigInt. Пустая денежная строка неизвестна. Счётчики целые неотрицательные; чеков и ФД может быть разное количество. При неизвестной фактической наличке разница неизвестна. Ненулевые возвраты и чеки владельца требуют уточнения их основы до сохранения. Бланки не заменяют кассовые/первичные документы.

## Настройки и история

Ограниченная схема правил, без eval и произвольного кода. Можно переименовать строки, скрыть их, включить/выключить использование, добавить до 20 своих строк с явным эффектом: выдача, внесение, неоплаченный чек в наличной выручке, справочная сумма. Скрытие не меняет математику. Ненулевые скрытые значения перечисляются на экране. Пустая скрытая обязательная строка требует заполнения; отключение ненулевой строки запрещено на клиенте и сервере.

Шаблон сохраняется как необязательное поле `worksheet` в существующих версиях настроек `catalog_revisions`: прежние категории/получатели сохраняются. Проверяются текущая версия, автор, причина, повтор запроса; изменения добавляют версию. Старый редактор категорий сохраняет настройки листа. Удаление настроек при обновлении категорий запрещено. Архив v1/v2 содержит соответствующие версии; новый валидатор проверяет и эту часть истории.

Новая смена хранит собственные исходные строки и снимок настроек. Изменение шаблона не переписывает прошлые результаты. Применение новых правил к сохранённому листу — отдельное действие с предупреждением, затем новая версия с причиной. Формула `cash-excel-v1`; старые формулы неизменны. Произвольная математика уровня Excel пока не реализована.

Служебный номер листа генерируется, не считается аппаратным номером смены. Повтор HTTP-запроса идемпотентен, но гарантировать обнаружение двух ручных вводов одного аппаратного отчёта без его идентификатора нельзя. Это ограничение упрощённого ввода. Старые смены открываются в `/advanced.html`, где прежние реквизиты и подробные функции доступны. Переход между режимами не конвертирует сохранённые данные молча.

## Реализация и проверка

`worksheet.mjs` — валидация шаблона, независимый предпросмотр наличных/безналичных, серверный расчёт. `domain.mjs` направляет новые листы в этот расчёт; прежние ветки расчёта не меняются. Сервер раздаёт новые статические файлы с прежними Host/Origin/CSRF/CSP-ограничениями. Настройки/история/архив используют существующую SQLite. Новых сервисов и сетевых портов нет.

103 автоматических теста: базовая математика, неизвестное/ноль, скрытие/отключение, возвраты/период, товары и деньги владельца, дополнительные движения, точные копейки, схема данных, конфликты настроек, неизменяемость старого снимка, архив и HTTP. Новый лист и оба прежних UI-сценария проверены в Chromium на четырёх размерах. Новый сценарий проверяет сохранение, скрытую выплату без изменения результата, сохранение настроек после перезагрузки, дополнительную выплату, историю исправлений, печатные данные и восстановление архива.

Это локальная тестовая версия без реальной авторизации, независимого подтверждения разрешений, LAN/внешнего доступа, импорта 1С и автоматических защищённых внешних копий. Физические Windows/Safari/iPhone/Android отдельно не проверены. Новые архивы проверять и восстанавливать версией 0.8+. Обновление через отдельную папку, после выгрузки/проверки архива и остановки прежнего процесса; папку данных не удалять.
