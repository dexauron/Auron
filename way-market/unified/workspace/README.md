# Way Market — TEST 0.7

Тестовая рабочая область с личными аккаунтами, кассой, задачами, расширенным каталогом, закупками, деньгами и зашифрованными копиями. Все семь направлений ещё не завершены: см. docs/WAY_MARKET_SEVEN_TASKS_STATUS.md.

## Запуск

Распакуйте в отдельную папку Way-Market-Workspace-Test-0.7. Требуется Node.js 24 x64; npm-пакеты обычному запуску не нужны. Остановите прежний тестовый сервер рабочей области, затем откройте start-workspace-test.cmd. На серверном компьютере откройте http://127.0.0.1:3211. При первом запуске создайте владельца по коду из окна сервера; пароль-фраза — от 15 символов. Только вымышленные данные.

Старое кассовое приложение на порту 3210 и его база остаются отдельными. База новой рабочей области: %ProgramData%\WayMarket-Workspace-Test\workspace-test.sqlite. Код первоначальной настройки не используется после создания владельца.

## Каталог и сопоставление

Владелец/администратор ведёт группы, карточки, несколько штрихкодов и упаковки. «Количество в упаковке» означает базовые единицы, а масса/объём — размер одной товарной единицы. Ведущие нули штрихкодов сохраняются. Причина изменения и текущая версия обязательны при редактировании.

В поиске попробуйте «молоко 0,9 л в наличии до 100 рублей». Локальные правила учитывают отдельные опечатки, раскладку и транслитерацию. Это не облачный ИИ и не универсальное понимание языка.

«Сопоставить название» доступно владельцу/бухгалтеру: выберите поставщика, вставьте точное название из накладной, проверьте товар и упаковку, явно подтвердите. Исходная строка сохраняется дословно. Баллы сходства не являются вероятностью. При различиях объёма/жирности и неизвестных признаках показываются предупреждения. Файловый импорт накладной ещё не подключён.

«Каталог покупателя» открывает /shop без входа, в пределах разрешённого сетевого доступа. Каждый товар нужно отдельно отметить «Показывать розничную карточку». По умолчанию карточки скрыты. Витрина не выдаёт кассовые коды, соответствия поставщиков и финансы. Список покупателя хранится в памяти страницы, допускает копирование текста; после перезагрузки исчезает. Это не заказ и не резерв. WhatsApp/отправка сообщений, фотографии и сканирование камерой ещё не подключены. Подробнее: docs/WAY_MARKET_CATALOG_STAGE.md.

## Деньги и расчёты

Раздел «Финансы» доступен владельцу/бухгалтеру. На телефоне откройте «Деньги и долги» с главной либо «Финансы» в меню аккаунта. Владелец создаёт наличные/банковские счета и проверенные начальные остатки. После первого движения начальные данные счёта фиксируются; остатки не считаются выручкой.

По накладной закупки нажмите «Подтвердить долг»: поставщик, дата и фактическая сумма берутся из накладной. Задайте срок и основание. Деньги при подтверждении не списываются. Можно записать ручной долг «мы должны»/«нам должны».

В карточке долга назначьте расчёт по выбранному счёту и сроку. Назначение денег не двигает. Кнопка «Записать исполнение» записывает фактическую сумму, включая частичную, с подтверждающим документом. Накладная 40 ₽, назначение 40 ₽ и оплата 15,01 ₽ оставляют долг и остаток назначения по 24,99 ₽. Закупочный лимит повторно не расходуется.

Поступление/списание/перевод — запись состоявшегося факта, с датой, назначением, основанием и явным подтверждением. Приложение не подключено к банку и не переводит деньги. Если известен уникальный номер операции на счёте, укажите его: повтор среди действующих записей блокируется. Без номера защищён только повтор той же команды, а не любая повторная ручная запись.

Отрицательный учтённый остаток требует пояснения и остаётся видимым расхождением. Не меняйте начальный остаток для скрытого устранения разницы.

Принятая сдача кассира отражается в деньгах отдельно, ровно на фактически пересчитанную сумму. Повтор одной сдачи блокируется. Изменение уже отражённой фактической суммы требует сначала исправить ошибочную запись денег, затем изменить сдачу и явно отразить новую версию. Выплаты, перечисленные в кассовом листе, из принятой сдачи повторно не списываются.

Проведённое движение не перезаписывается. Владелец может исправить ошибочную запись о несостоявшемся движении отдельной обратной записью с причиной и датой. Это не реальный возврат денег: физический возврат оформляется новым движением. Исходные записи сохраняются.

## Ручная сверка банка

Внесите строку проверенной выписки: банковский счёт, уникальный номер, дату, направление и сумму. Сопоставьте с записью журнала. Строка сверки не проводит деньги повторно. Различия сумм/дат и исправленные движения остаются заметны. Ошибочно перенесённые исходные данные строки не перезаписываются: отмените ошибочный ввод с причиной, затем внесите правильный. Автоматический импорт/подбор и сверка эквайринга ещё не подключены.

Отчёт за период показывает остатки и движения по каждому счёту, включая отдельно введённые в периоде начальные остатки. Это не отчёт о прибыли. Переводы видны на обоих счетах, корректировка — на своей дате.

Подробности и границы: docs/WAY_MARKET_FINANCE_STAGE.md. Табель/зарплатные начисления, подотчёт, авансы, независимые согласования, распределение платежа по нескольким накладным и полноценный кабинет ТП ещё не реализованы.

## Закупки

Владелец/администратор добавляет товары в ручной каталог. Владелец/бухгалтер ведёт поставщиков, заказы и приёмку; лимит задаёт только владелец. Заказ резервирует лимит. Приёмка записывает фактическое количество и цену; частичная оставляет резерв недопоставленного, окончательная освобождает остаток с отражением недовоза. Приёмка не создаёт платёж или складское движение автоматически. См. docs/WAY_MARKET_PROCUREMENT_STAGE.md.

## Копии и обновление

Перед испытанием обновления создайте и проверьте копию прежней версии. Для испытания используйте отдельную восстановленную тестовую базу. Новая версия добавляет таблицу расширенного каталога; прежние записи остаются. Старые накладные/сдачи не создают автоматические движения денег.

Новый зашифрованный архив v5 включает все версии каталога, соответствия поставщиков, финансы, сверку банка, аудит и ключи повторов. Читаются архивы v1/v2/v3/v4 с пустыми отсутствующими таблицами. Восстановление создаёт отдельную базу, не переключает действующую и не переносит сеансы. Старое приложение не открывает обновлённую схему/архив: для отката нужна отдельная база из прежней копии. Не удаляйте папку данных.

Владелец создаёт, скачивает, проверяет и восстанавливает копию в разделе «Резервные копии». По умолчанию копии на том же SSD: перенесите файл на отдельный носитель, пароль храните отдельно. После перезапуска расписание снова требует пароль. Автоматического удаления старых копий нет. Предел копии — 32 МиБ содержимого / 100 000 строк. Без пароля расшифровка невозможна.

Обычный запуск ограничен 127.0.0.1. Отдельные prepare-workspace-https-test.cmd и start-workspace-https-test.cmd описаны в docs/WAY_MARKET_HTTPS_STAGE.md. Новая папка должна называться Way-Market-Workspace-Test-0.7; код новой папки также должен пройти проверку Windows ACL. Для HTTPS нужна свежая копия с финансовыми документами, каталогом и проверенным восстановлением. Старые сертификаты/конфигурация автоматически не заменяются. Пароль PFX вводится скрыто при запуске.

На AURON-SERVER скрипты автоматически не исполнялись. Windows Server, Safari/iPhone, гостевая сеть, физический принтер и реальная нагрузка требуют отдельного испытания. Интернет-доступ и служба автозапуска не реализованы. Серверные черновики сохраняются только кнопкой; работа без связи не подключена.

## Проверки разработчика

npm test — сценарии рабочей области, копий, черновиков, закупок, финансов и каталога. npm run test:https — HTTPS-проверки; OpenSSL нужен только для генерации тестовых сертификатов. Проверки в Node 24/Linux/Chromium не заменяют испытание на реальном сервере магазина.
