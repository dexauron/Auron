# Way Market — рабочая область TEST 0.2

Отдельный испытательный веб-сервер с личными аккаунтами. Это не полная версия приложения по ТЗ и не обновление прежней кассовой базы.

## Запуск на Windows

1. Распакуйте архив в новую папку. Не заменяйте старое приложение и не переносите базы.
2. Откройте `start-workspace-test.cmd`. Требуется установленный Node.js 24 x64; дополнительные npm-пакеты не нужны.
3. В браузере серверного компьютера откройте `http://127.0.0.1:3211`.
4. На первом запуске в окне сервера появится код первоначальной настройки. Введите его в приложении, задайте имя, логин и пароль владельца. Пароль-фраза — от 15 символов. Общего пароля нет.
5. В разделе «Сотрудники» создайте личные аккаунты. Доступны владелец, администратор, бухгалтер, кассир, сотрудник и представитель.

Остановка — Ctrl+C в окне сервера. После повторного запуска аккаунты и сохранённые записи остаются в новой базе. Код первоначальной настройки после создания владельца больше не используется. Не публикуйте код, пароль или саму базу.

## Что можно проверить

- Войти кассиром, отправить собственную сдачу; войти бухгалтером и принять деньги с независимым пересчётом.
- Посмотреть историю версий, исправить с причиной, распечатать сохранённую версию.
- Создать сотруднику задачу и выполнить её из его аккаунта.
- Добавить товар владельцем/администратором и найти его из рабочего каталога сотрудника.
- Отключить сотрудника, проверить завершение его сеанса; посмотреть журнал владельцем.
- Владельцем создать зашифрованную копию, скачать/проверить её, восстановить отдельную базу и настроить расписание.

Пароли и токены не хранятся в открытом виде в базе; сведения сотрудника не сохраняются в браузерном хранилище. Сохранение кассы и аудит выполняются одной транзакцией. Это не заменяет полный аудит безопасности.

## Данные и ограничения

Новая база: `%ProgramData%\WayMarket-Workspace-Test\workspace-test.sqlite`. Старый путь `%ProgramData%\WayMarket-Test\cash-test.sqlite` не используется. Схемы несовместимы — не открывайте одну базу другим приложением. Порт новой области 3211; прежняя касса использует 3210.

Только вымышленные данные. Новая копия `.wmbackup` включает аккаунты, кассу, задачи, каталог, журнал и ключи повторов. Старый JSON-архив кассы её не архивирует. Восстановление создаёт отдельную базу и не заменяет действующую. Вложения ещё не поддерживаются. Не вводите рабочие суммы и персональные сведения до завершения остальных проверок и модулей.

Копии по умолчанию находятся в `%ProgramData%\WayMarket-Workspace-Test\backups` на том же SSD. Скачайте файл на другой физический носитель и храните пароль отдельно. Без пароля копия не расшифруется. На другом компьютере/после поломки носителя файл нужно поместить в выбранную папку резервирования для проверки; загрузка файла браузером пока отсутствует. Папку может заранее выбрать оператор через абсолютный `WAY_MARKET_BACKUP_DIR`.

Расписание работает только пока запущен сервер и его владелец сохраняет полномочия. После перезапуска нужно снова включить расписание с паролем; ключ не сохраняется открытым текстом. В интерфейсе будет предупреждение. Старые копии автоматически не удаляются — следите за свободным местом. Текущий предел копии: 32 МиБ содержимого, до 100 000 строк.

Вход с других компьютеров/телефонов пока не включён: сервер слушает только 127.0.0.1. Нельзя самостоятельно открывать его в интернет или обходить ограничение прокси-сервером. Нужны HTTPS, полное резервирование и остальные проверки сетевого запуска.

Несохранённый ввод кассы находится только в памяти страницы; восстановление черновика после перезагрузки пока отсутствует. Есть предупреждение при уходе. Закупки, лимиты, табель, расчёт зарплат, полноценный кабинет ТП, ИИ, исходный каталог, импорт, PWA и служба Windows ещё не подключены. Все функции ТЗ этой сборкой не объявляются завершёнными.

Проверены автоматические сценарии в Node 24/Linux и Chromium на ширинах 1440/390/320 px. Windows, Safari, физический принтер и реальная нагрузка требуют отдельного испытания.

При обновлении остановите прежний сервер рабочей области на порту 3211 и распакуйте новую сборку в отдельную папку. Папку данных в ProgramData не удаляйте. Прежнее кассовое приложение на 3210 и его база остаются отдельными.
