# Way Market — локальная тестовая сверка 0.8.3

Первый сохраняемый сценарий новой системы. Только синтетические данные и один локальный пользователь. Это не готовая финансовая программа, не смена 1С и не проведение платежей.

## Безопасность черновиков в 0.8.3

Черновик хранится отдельно для каждого сеанса редактирования и вкладки. Сохранение листа на сервере удаляет только его текущую копию браузера. Другие вкладки, листы и правки того же листа сохраняют свои копии. Дублированная вкладка получает отдельный редактор; где доступен Web Locks, активную чужую копию нельзя удалить. Если Web Locks недоступен, используются новые ID редакторов: восстановление доступно, удаление чужой копии ограничено.

При наличии черновиков появляется кнопка «Открыть». Можно выбрать нужный по дате, кассиру и времени. Восстановление поверх текущего ввода требует подтверждения; текущий ввод сохраняется отдельной копией, если хранилище доступно. Перед восстановлением повторно проверяются снимок и версия листа на сервере. Устаревший черновик сохраняется, текущие поля не заменяются. Явно отброшенное исправление больше не предлагается после открытия другого листа.

Сбой записи/чтения браузерного хранилища показывается рядом с кнопкой сохранения. Ввод остаётся на экране, сохранение на сервере доступно. Черновик браузера не заменяет архив базы. Восстановленные копии из другой вкладки и старого формата 0.8.2 не удаляются автоматически; ненужную копию можно удалить отдельно. Хранилище остаётся открытым текстом в профиле браузера, реальных ролей пока нет.

Проверено: 114 автоматических тестов, 6 изолированных браузерных сценариев черновиков и прежний полный сценарий Claude с четырьмя размерами экрана. В том числе: две вкладки, дублированная вкладка, две правки одного листа, отмена/подтверждение восстановления, отказ хранилища на экране 320 px, старый формат черновика и сохранение на сервере при отказе localStorage. Формулы, SQLite и формат архива не менялись. Подробности — `docs/WAY_MARKET_DRAFT_SAFETY.md`.

## Удобство ввода в 0.8.2

Структура и расчёт листа прежние. Изменено поведение ввода:

- Enter переходит на строку ниже и не сохраняет лист.
- Суммы можно вводить как в документе: «34 000,50».
- Пустая строка подсказывает «впишите 0, если не было»; все пропуски видны у кнопки.
- Сохранение и состояние листа — на закреплённой панели внизу.
- Прежние версии открываются только для просмотра.
- «Настроить» ведёт к нужному правилу и возвращает к листу.
- Несохранённый лист можно восстановить после закрытия браузера.

Подробности, проверки и порядок обновления — `docs/WAY_MARKET_CASH_UX_HANDOFF.md` в репозитории. 105 автотестов и браузерная проверка `way-market/audit/cash-sheet-browser-check.mjs` прошли. Формула, база и архив не менялись: откат на 0.8.1 возможен.

## Знаки и цвета расхождений в 0.8.1

Положительная разница показывается с «+» зелёным, отрицательная — с «−» красным. Ноль нейтрален, неизвестное значение не получает знак и цвет. Единое оформление применяется в новом листе, прежнем подробном режиме, истории и печатных расхождениях. Формулы, сохранённые суммы и база не меняются. Печатный цвет зависит также от настроек принтера; знак сохраняется при чёрно-белой печати.

## Кассовый лист по Excel в 0.8

Основной адрес `/` показывает привычный лист: дата, принимающий кассу, кассир, число чеков и ФД. Два виджета — «Наличка» и «Эквайринг» — повторяют строки пользовательского шаблона. Фактическая наличка и итоговый отчёт находятся ниже. На основном экране нет переключателей формул, способов ввода и обязательных служебных реквизитов. Один вопросительный знак у каждого блока открывает объяснение. Слева на компьютере и снизу на телефоне — три раздела: лист, история, настройки.

Названия, показ/скрытие, включение дополнительных движений, свои строки и ограниченный набор правил расчёта сохраняются на сервере в истории настроек. У новых листов используются сохранённые настройки; у старых — снимок правил той версии. Настройки не переписывают прошлые результаты. Чтобы применить новые правила к сохранённому листу, есть отдельная кнопка; затем требуется причина исправления. Настройки и исходные суммы входят в архив. Скрытая строка с суммой продолжает учитываться и показывается отдельным сообщением; отключить ненулевую строку нельзя. Неизвестное не подменяется нулём. Если движение не используется, это нужно явно задать в настройках.

Правила: инкассация с внесением либо продажи без внесения; возвраты уже учтены / вычесть / другой период; чеки владельца — деньги, товар внутри наличной выручки либо вне её. При ненулевых возвратах и чеках владельца без выбранного правила сохранение блокируется. Накопительный возврат из ФН не вычитается автоматически из текущей смены. «Общая торговля» включает наличные через эквайринг и безналичные кассы; терминал сверяется отдельно. Это исправляет пропуск второго наличного источника в исходном Excel. Настройки определяют математику, но не подтверждают реальность движения или разрешение на него.

Номер нового листа генерируется автоматически и не выдаётся за номер аппаратной смены. Без реального идентификатора кассовой смены приложение не может надёжно определить повторный ручной ввод одного физического отчёта. Повтор HTTP-запроса защищён прежней идемпотентностью. В подробном режиме по-прежнему доступны касса, номер смены, отдельный автор, категории и получатели. Старые записи открываются там без пересчёта; новые листы открываются в новом интерфейсе. Интеграции 1С, независимые согласования и вход по ролям ещё не реализованы.

103 автоматических теста прошли. Новый и прежний интерфейсы проверены в Chromium при 1440×1100/1000, 820×1180, 390×844, 320×740. Проверены скрытые суммы, настройки после перезагрузки, добавление выплат, сохранение версий, печатные данные и восстановление архива. Физические iPhone/Safari/Android и Windows отдельно не проверены. Программа остаётся локальной тестовой на 127.0.0.1; реальные данные пока не вводить.

Перед обновлением выгрузите и проверьте архив, остановите старый процесс, распакуйте новую версию в отдельную папку и запустите `start-server-test.cmd`. Путь тестовой базы прежний. Папку `C:\ProgramData\WayMarket-Test` не удалять. Новые формулы и настройки требуют 0.8 или более новой совместимой версии при записи, экспорте и восстановлении. Структура архива остаётся v1/v2; старое приложение отклонит новую формулу при проверке.

## Предыдущий подробный экран 0.7 — теперь /advanced.html

Ввод и расчётный отчёт находятся на одной странице по структуре бухгалтерского Excel: смена сверху, наличные и выплаты слева, эквайринг справа, передача и итог ниже. На телефоне блоки идут друг под другом с прокруткой, меню закреплено внизу. Светлые сгруппированные поверхности, системный шрифт, синие действия и крупные итоговые суммы. Это веб-интерфейс, а не нативная программа Apple. Пояснения скрыты за «?», ошибки остаются видимыми. Диалог закрывается кнопкой или Escape и возвращает фокус.

Можно перенести наличные продажи либо инкассацию, включающую внесение. Во втором случае программа выделяет продажи вычитанием указанного внесения один раз; фактические начальные/оставленные наличные вводятся отдельно. Итог терминала можно ввести общей суммой или по карте, QR, Bluetooth и био, с автоматическим сложением и проверкой на сервере. Основа «после возвратов» или «продажи и возвраты отдельно» сохраняется. Количество чеков и ФД за смену необязательно и не влияет на деньги.

«Общая торговля» включает наличные и безналичные кассы. «Наличные продажи по пересчёту» восстанавливают только наличную часть из фактически принятой бухгалтером суммы; это не общая выручка. Неизвестное не превращается в ноль. Реальные фотографии, имена и числа пользователя в демо не включены. Старые записи не переписываются, новые исходные поля входят в историю, печать и архив. Для новых архивов используйте 0.7 или более новую совместимую версию.

Проверено: 90 автоматических тестов и Chromium при 1440×1000, 820×1180, 390×844, 320×740: ввод, точная сумма источников, подсказки, клавиатура, сохранение, история, печатные данные, отсутствие горизонтального переполнения. Реальные Safari/iPhone/Android и Windows отдельно ещё не проверены. Сервер остаётся только 127.0.0.1, без авторизации и доступа из сети.

## Свои категории и получатели в 0.6

В «Настройках» добавляйте, переименовывайте и отключайте категории и необязательных получателей. У категории выберите, что произошло: выдача наличных, внесение или товар без оплаты. Название само по себе не определяет знак расчёта. Укажите автора и причину изменения, сохраните настройки. История хранится на сервере; отключение не удаляет старые смены.

В разделе выплат выберите «Свои категории». Основное в записи — категория и сумма; получатель, основание и общая/отдельная операция — в подробностях. Можно общей суммой по одной категории и подробностями по другой. Общий итог и его детали в одной категории вместе запрещены. Прежние суммы и записи нужно явно убрать/обнулить перед переходом: программа не удаляет их молча. При обратном переходе записи категорий тоже не пропадают незаметно.

Деньги владельцу вычитаются как физическая выдача. Неоплаченный товар — отдельная корректировка только если его чек уже включён в наличную выручку; ответ обязателен. Если не включён, наличные не уменьшаются. Это не расход для прибыли. Сумму одного события не повторять как выдачу и как неоплаченный чек. Внесения вводить либо по категориям, либо в прочих поступлениях.

Смена хранит снимки названия/правила; новые настройки не меняют старые результаты. Справочник, его история и запросы входят в архив версии 2 при наличии изменений. Новые архивы/формулы проверять и восстанавливать версией 0.6 или совместимой более новой. Не использовать старую программу для записи/экспорта обновлённой базы. Путь базы прежний, добавляется только таблица истории справочника. Перед обновлением выгрузите и проверьте прежний архив, затем остановите старый процесс и распакуйте новую программу в отдельную папку. Папку данных не удалять.

Подробности: `docs/WAY_MARKET_CATEGORIES.md` в репозитории. Реальные роли и независимые согласования ещё не реализованы; введённые имена авторов не подтверждаются входом.

## История интерфейса: ввод в 0.5 (заменён одной страницей в 0.7)

Пять шагов вместо длинной формы: смена, наличные, выплаты, терминал, проверка. Подробности раскрываются рядом с нужным действием. «Не было» явно устанавливает 0; пустые данные остаются неизвестными. При ошибке «Далее» раскрывает нужную группу и указывает поле. Нажатие Enter на раннем шаге не сохраняет незавершённую форму.

«Вся форма» показывает все поля без изменения сумм, способа расчёта или истории. На последнем шаге видны наличный результат и отдельный статус безналичной сверки; кнопка этого статуса возвращает к терминалам. На телефоне — одна колонка и нижняя навигация; на компьютере — боковое меню и две колонки проверки. Все возможности остаются доступны при любой ширине.

Формулы, SQLite и серверная защита не менялись. Поддержка современного браузера — целевой способ доступа с Windows, Linux, macOS, Android и iPhone; фактически проверен Chromium на Linux в размерах 1440×1000, 820×1180, 390×844 и 320×740. Это не тесты реальных iPhone/Safari/Android. Доступ с других устройств пока не включён: сервер по-прежнему только 127.0.0.1. Решения и ограничения — `docs/WAY_MARKET_SIMPLE_UX.md` в репозитории.

## Сверка в 0.4

В наличной сверке можно включить второй источник наличных продаж после возвратов. Складывать источники только если они не пересекаются. «Остаток на начало» — физические деньги, а не произвольный счётчик кассы; начальный размен и внесение не дублируются. Внесения и предыдущие передачи вводятся по фактическому движению: сервисный чек сам по себе его не доказывает.

Выплаты — общими наличными суммами: поставщикам, зарплата/авансы, другие выдачи; либо подробными записями. Одновременный ввод общих сумм и подробностей блокируется, не удваивает расход. При переключении режима прежние значения не удаляются автоматически: удалить ненужные записи/обнулить ненужные общие суммы нужно явно. Чекбокс фактической основы — заявление автора теста, не подтверждение разрешения. В подробном режиме «выполнена» означает физическую выдачу, а не разрешение бухгалтера. Фактическая выдача без разрешения не должна исчезать из расчёта.

Безналичные: общий итог кассы и терминалов. У каждого источника выбрать готовый итог после возвратов либо продажи до возвратов и возвраты отдельно. Нельзя повторно вычитать возвраты из готового итога. Разница = терминалы − касса; требуется подтверждение сопоставимости периода и полного набора терминалов. Источник отчёта обязателен. Неизвестное не равно нулю. QR/Bluetooth не объявляются картой или СБП без настройки. Комиссия/зачисление банка — отдельные будущие функции.

Пример полностью вымышленный: наличные к передаче 25 000 ₽, принято 24 800 ₽, разница −200 ₽; безналичные кассы 58 000 ₽, терминалов 57 900 ₽, разница −100 ₽. Поставщики 7 500 ₽ и зарплата 1 000 ₽ вводятся общими суммами. Нет реальных реквизитов магазина. Старые смены открываются в прежнем режиме, добавление новых полей создаёт новую версию с причиной. Формулы `cash-net-v1` и `cash-multi-source-v2` различаются; старые снимки не переписываются.

Обязательные согласования, роли кассира, уведомления и обработка ошибочных разрешений описаны в `docs/WAY_MARKET_CONTROL_AND_APPROVALS.md` репозитория. Это проект следующего этапа, не работающая функция 0.4.

Перед обновлением 0.3 создать/проверить архив через «Копии данных», остановить сервис Ctrl+C и распаковать новую программу в отдельную папку. Запуск тем же `start-server-test.cmd` открывает прежнюю серверную базу. Саму папку данных **не удалять**. Новые архивы с безналичной сверкой восстанавливать 0.4 или совместимой более новой версией.

## Для выделенного компьютера AURON-SERVER

По решению владельца данные новой системы должны храниться централизованно на выделенном сервере, а не в отдельных базах сотрудников. Целевая схема и незавершённые условия безопасности — `docs/WAY_MARKET_SERVER_DECISION.md` в репозитории.

Для первого теста на Windows Server после установки Node.js 24 используется **start-server-test.cmd**. Он открывает `%ProgramData%\WayMarket-Test\cash-test.sqlite`, обычно `C:\ProgramData\WayMarket-Test\cash-test.sqlite`. Папка не зависит от вошедшего Windows-пользователя. Нужны права на её создание и запись; скрипт не выдаёт их автоматически. В production права будут назначены выделенной служебной учётной записи.

Если уже использовалась версия 0.1/0.2 и серверный запуск обнаружил прежнюю базу текущего пользователя, но не серверную, он остановится: сначала выгрузить и проверить архив старой базы, затем восстановить в новый серверный файл по инструкции ниже. Не удалять старую базу для обхода предупреждения. Другие пользовательские профили автоматически не сканируются.

Сейчас тестовый интерфейс открывается **в браузере сервера через RDP**, адрес `http://127.0.0.1:3210`. Доступ с других устройств ещё не включён. Командный файл не устанавливает службу Windows: выход из учётной записи или завершение процесса останавливает программу. Пользователям магазина в будущем нужен вход в веб-приложение, не RDP под администратором.

## Запуск Windows

1. Установить поддерживаемую исправленную версию **Node.js 24 x64** с официального https://nodejs.org/. Перезапустить терминал после установки. Зависимости npm устанавливать не нужно.
2. Распаковать эту папку целиком в отдельную папку, например `C:\WayMarket-Test\local-app`.
3. Для прежнего пользовательского теста запустить `start-windows.cmd` обычным пользователем. Для центральной тестовой папки сервера — `start-server-test.cmd` (описано выше). Это разные базы, автоматически они не сливаются.
4. Дождаться сообщения `Way Market TEST`, открыть **http://127.0.0.1:3210** в браузере **на сервере** (можно через уже подключённый RDP).
5. Нажать «Заполнить пример», проверить 25 000 ₽ к передаче и −200 ₽ расхождения, сохранить. Обновить страницу, открыть историю — запись должна остаться. Исправить пересчёт на 25 000 ₽, указать причину, сохранить версию 2, распечатать.
6. Остановка — Ctrl+C в окне запуска. Для повторного запуска открыть тот же CMD. Если порт занят, второй экземпляр сообщит об ошибке; не завершать незнакомые процессы автоматически.

Выполнены Linux/Node 24 и Chromium проверки. Вся папка нужна целиком; HTML отдельно не работает. Интернет при запуске не нужен. ИИ и внешние сервисы отсутствуют.

## Данные

На Windows база создаётся в `%LOCALAPPDATA%\WayMarket-Test\cash-test.sqlite` текущего пользователя. На другой ОС — `~/WayMarket-Test`. Это отдельная тестовая база, не старый Auron Finance. Файл не публикуется HTTP-сервисом. При смене Windows-пользователя путь и база меняются.

SQLite: WAL, synchronous FULL, BEGIN IMMEDIATE, уникальная смена (дата + касса + номер), версии и идентификаторы запросов. Исправление добавляет снимок и причину, старую версию не переписывает. Версия формулы сохранена. Это история внутри приложения, **не защита от администратора**, который может изменить файл базы. Добавлен проверяемый JSON-архив и восстановление в новый файл. Внешняя копия и расписание сами не настраиваются. Не копировать только основной файл работающей WAL-базы как резервную копию.

## Архив и пробное восстановление

В разделе **«Копии данных»** нажать «Скачать архив». В него входят все смены (не только последние 100 на экране), все версии, исходные значения, сохранённые итоги и записи защиты от повторов. Несохранённый ввод не включается. Снимок создаётся в одной транзакции чтения. Предел этого тестового формата — 10 000 версий и файл 16 МиБ; превышение явно отвергается, архив не обрезается.

Перенести скачанный JSON на отдельный защищённый носитель. Архив **не зашифрован** и содержит имена и суммы; не отправлять его в публичный GitHub, чаты или сторонний ИИ. Нажать «Проверить архив», выбрав скачанный файл: проверяются структура, SHA-256, уникальность, непрерывность истории, связи запросов и повторный расчёт по поддерживаемой версии формулы. Проверка ничего не импортирует в активную базу. Контрольная сумма не является подписью и не защищает от намеренного изменения администратором.

Для пробного восстановления открыть PowerShell в папке приложения. Указать реальный путь архива и **новое, ещё не существующее имя базы** на локальном NTFS-диске. Пример команды (пути заменить):

```powershell
node .\restore.mjs "C:\WayMarket-Test\archive.json" "C:\WayMarket-Test\recovered-test.sqlite"
```

Родительская папка назначения должна существовать. Скрипт проверяет архив, восстанавливает его в отдельную временную SQLite, повторно считывает и сравнивает записи, закрывает базу и только после этого публикует новый файл. Если файл назначения существует — отказ без перезаписи. Публикация использует атомарное создание hard link на том же томе; неподдерживаемая файловая система даёт ошибку, а не небезопасную замену. Не выбирать сетевой ресурс или рабочий файл `cash-test.sqlite`. Архив не содержит и не исполняет SQL.

Чтобы посмотреть восстановленную копию, сначала остановить обычный тестовый сервис Ctrl+C, затем выполнить **отдельным шагом**:

```powershell
node .\server.mjs --recovered-test "C:\WayMarket-Test\recovered-test.sqlite"
```

Открыть http://127.0.0.1:3210 и сверить историю/суммы. Изменения при таком запуске сохраняются в восстановленную копию. Обычная база автоматически не заменяется. После проверки остановить сервис; `start-windows.cmd` снова открывает прежнюю обычную тестовую базу. Это не процедура переключения рабочей системы после аварии; ролей и готового production-backup пока нет.

## Правила

- Суммы вводятся текстом в рублях, преобразуются в целые копейки без floating-point разбора. Пробелы-разделители тысяч, экспоненты и более двух десятичных знаков отвергаются. Отрицательный ввод разрешён только для готового безналичного итога периода после возвратов. Максимум одного ввода по модулю — 999 999 999,99 ₽; арифметика наличного итога BigInt с проверкой диапазона.
- Наличные по Z должны уже учитывать возвраты, но ещё не вычитать перечисленные выплаты. Эта основа явно подтверждается. Другие форматы Z пока нужно сверить до использования; универсальной настройки формулы ещё нет.
- Ожидаемая передача = начало + наличные Z + прочие поступления − выполненные выплаты наличными − оставлено. Выплата картой/СБП и невыполненная выплата не уменьшают наличные.
- Заявление кассира и пересчёт бухгалтера — отдельные необязательные значения; пусто ≠ 0. Если пересчёт заполнен, имя бухгалтера обязательно. Имена являются введённым текстом, не подтверждённой идентичностью.
- Факт минус расчёт и принято минус заявлено — разные расхождения. Отрицательный расчёт отображается с предупреждением. Расхождение не считается доказанным хищением.
- Дата/касса/номер сохранённой смены неизменяемы в этом этапе. Для исправления ошибочной идентичности потребуется будущий сценарий отмены; не создавать второй документ вместо первого без разбора.
- Повторный запрос с тем же ID и содержимым возвращает ту же версию. Тот же ID с другим содержимым отвергается. Конкурентная устаревшая версия не перезаписывает новую. Одинаковая смена с другим request ID не создаётся.
- Печать берёт сохранённый снимок, не текущие несохранённые значения; бумажные подписи отдельно. Печатный тестовый бланк не заменяет обязательные формы бухгалтерского учёта.

## Сеть и доступ

Сервис слушает только **127.0.0.1:3210**. Нет параметра включения LAN. Не публиковать через туннель или reverse proxy и не открывать порт в роутере. Проверяются Host, Origin/Fetch-Site, CSRF-токен и размер запроса. Токен — защита от запросов посторонней веб-страницы, **не авторизация пользователей**. Другие программы и пользователи этого компьютера с локальным доступом не изолированы. Нет CORS, удалённых шрифтов, CDN, подключений к старым базам и ключей OpenRouter.
